Named SSH connections

Burrow manages a real shell-free OpenSSH master through the single burrow@0.1.0 public-SDK Hovel module. The CLI and Catppuccin terminal interface share the same commands. The connection lifecycle in issue #45 and authentication baseline in issue #46 establish actual SSH access in MVP 1. Interactive shells and tunnels follow in MVP 2; Saved profile collections preserve recipes for later sessions; transfers remain a separate ticket.

One public module

Setup installs only burrow@0.1.0; each connection still has its own retained owner process/session. The frontend supplies workspace and non-secret connection JSON to that module through a normal Hovel chain and confirmed throw. Saved-profile management uses the same module’s command input. Hovel’s module-wide dangerous tag requires --allow-dangerous for all its throws, including workspace inspection and profiles. Private authentication, host verification, profile review, launch-key policy and persisted plans/confirmations remain enforced.

Existing workspaces from before issue #76

Opening an existing workspace installs/updates the base module without terminating existing owners or rewriting old chains. Temporary compatibility recognizes only retained burrow-connection@0.1.0 connection sessions: use the normal connections, inspect, profile save and reviewed close commands. New connects use the base module. Name reservations prevent duplicate creation; unavailable owners or unknown reservations still require manual investigation. This compatibility does not register or relaunch the old module. The retired connection-module entry point refuses new invocations with transition guidance.

Old cached executables and catalog entries may still launch old chains until you retire those submissions. Use session list --json in the workspace’s Hovel CLI to identify sessions whose moduleId is burrow-connection@0.1.0; match their names/session IDs to Burrow’s connection inspection. To finish transition, stop all legacy chain submissions, inspect and explicitly close every old owner when its resources are no longer needed, then use the workspace’s Hovel CLI to run module uninstall burrow-connection@0.1.0. Do not uninstall while old owners are needed. For future runs, create/review a chain selecting burrow@0.1.0, set workspace to match the connection JSON, and use throw --allow-dangerous. Preserve historical chain configuration, runs, saved profiles, trust and collected evidence; setup never deletes or silently rewrites them. If owner identity or cleanup is uncertain, leave the registration and runtime intact for investigation. Prototype/research module names are historical proof fixtures, not production installation choices.

Connect and inspect

burrow --workspace /absolute/workspace status
burrow --workspace /absolute/workspace connect
burrow --workspace /absolute/workspace connect gateway server.example ubuntu --prompt
burrow --workspace /absolute/workspace connect gateway server.example ubuntu --key /absolute/key
burrow --workspace /absolute/workspace connect gateway server.example ubuntu --key /absolute/key --yes
burrow --workspace /absolute/workspace inspect gateway
burrow --workspace /absolute/workspace connections

First select and launch a verified workspace. Connection commands never start a replacement daemon. The required fields are name, host and user; - selects the configured SSH username. Options may appear before, between or after positional fields: --key PATH, --agent PATH, --port NUMBER (SSH config or 22), --ssh-config PATH (default ~/.ssh/config), --jump [USER@]HOST[:PORT][,...], --known-hosts PATH, --trust SHA256:FINGERPRINT, --prompt, and --yes. Quote paths containing spaces. The default agent socket comes from the frontend's SSH_AUTH_SOCK and must be accessible to the daemon. Hovel does not refresh its environment when an agent is started or changed later; select the current socket through the frontend's environment or --agent.

Only bare connect opens guided entry: a single editable form followed by resolved review, authentication and an observed result. Fields and named-command suggestions follow LazySSH order: host/IP, port, username, connection name, then optional settings. Example placeholders explain each input; Up/Down, Tab/Shift+Tab or a click selects a field in the TUI. Smaller terminals scroll the form to retain the focused field. Complete commands still accept flags in any order. Argument-bearing incomplete commands report validation errors; complete commands keep their one-line workflow. TUI forms stay in the centered, dimmed management popup. Passwords and encrypted-key passphrases use hidden Huh input over the private authentication transport. Escape or Ctrl+C cancels the active form or attempt, leaving management visible while cleanup completes.

Confirmations default to rejection: Tab or Left/Right chooses, Enter confirms, and Escape cancels. A TUI connect without --yes asks for operation approval; --yes skips that approval but never host-key verification. CLI commands remain noninteractive unless bare connect or --prompt requests forms. CLI forms read and render on the controlling terminal, preserving redirected JSON stdout and restoring terminal modes after cancellation. Authentication has a two-minute limit and three password attempts. Secrets never become command arguments or review values.

Named command compatibility

connect -ip server.example -port 22 -user ubuntu -socket gateway -ssh-key "/absolute/key with spaces" --yes

The same syntax works after burrow --workspace PATH. The mapping follows pinned LazySSH command source and command tests: -socket supplies the connection name, -ip the host or alias, -user the username, -port the port, and -ssh-key the key path. Unlike LazySSH, the port may use SSH config/22 and the socket path remains workspace-owned. Duplicate fields, including aliases such as -ssh-key with --key, are refused. -proxy, -shell and -no-term are explicitly unsupported; adding forms does not implement tunnels or interactive shells. Bracketed paste edits the command without executing embedded newlines.

Interactive success means the owner verified the master socket. Failed or cancelled interactive attempts close their own retained owner and reservation; cleanup uncertainty is reported and unknown files remain untouched. Noninteractive --yes registers an asynchronous attempt: inspect its connecting, connected or lost state. A failed asynchronous attempt remains owned until explicit close or reconnect. Hovel records the launch plan and confirmation through its ordinary dangerous-operation and launch-policy flow, in the burrow operation with a distinct chain per attempt.

After successful interactive authentication, Burrow offers to save reusable settings. See saved connection collections for the automatic JSON template, saving an active connection, selecting files, backup and reopen examples.

Aliases and jump hosts

burrow --workspace /absolute/workspace connect gateway my-ssh-alias - --prompt
burrow --workspace /absolute/workspace connect internal target.example ubuntu --jump bastion --prompt

OpenSSH evaluates the operator's trusted local configuration using ssh -G, including Include and Match processing. Match exec remains local executable configuration, so choose configuration you trust. Burrow imports HostName, User, Port, IdentityFile, IdentityAgent and ProxyJump into a private per-connection configuration. Explicit endpoint/key options override the corresponding config values. Multiple identity files and up to eight jump hops are supported; cycles are refused. Each hop uses OpenSSH's native ssh -W forwarding. Burrow supplies the same host-trust policy to all hops; config forwarding, local/remote commands, arbitrary ProxyCommand, host-trust overrides and agent forwarding are not imported. Optional certificate/hardware/MFA customization is outside this baseline.

Host trust

Alias authentication also preserves IdentitiesOnly. A host-specific IdentityAgent (including none) takes precedence over the frontend environment; an explicit --agent takes precedence over both. Jump hosts resolve their own agent settings independently rather than inheriting the target's resolved agent.

Existing trust comes from the selected OpenSSH known-hosts file (default ~/.ssh/known_hosts) and private W/burrow-known_hosts. OpenSSH verifies keys during the actual handshake, including targets reachable only through jumps. An unknown host requires terminal approval with --prompt, or an independently verified --trust SHA256:FINGERPRINT. Read the host identity and fingerprint and verify them through a separate trusted channel before choosing Trust host. Rejection is selected initially. A fingerprint supplied for one key never approves a different key elsewhere in the jump path.

An approval appends public host-key data to the workspace trust file. That file survives connection close. Changed or revoked keys are refused, including when --trust is supplied. Burrow does not silently update trust, use insecure host-key options, or forward SSH banners and raw authentication diagnostics into logs or the terminal.

The combined trust snapshot is limited to 1 MiB. Oversized workspace or selected known-hosts data is refused before SSH starts; entries are never silently truncated. Select a suitably scoped known-hosts file if the combined data exceeds this bound.

OpenSSH askpass answers travel through a short-lived 0700 directory and same-user Unix socket to the requesting frontend, then through an anonymous pipe to OpenSSH. Hovel receives non-secret settings and the temporary endpoint only; passwords, passphrases and private-key contents never enter chain configuration, RPC inputs, histories, artifacts or logging. Direct Hovel automation can use keys/agents; interactive secrets require the live Burrow frontend. This is in-memory credential delivery, not a vault, and does not isolate secrets from a hostile process running as the same user.

Retention, reconnect and close

burrow --workspace /absolute/workspace reconnect gateway server.example ubuntu --key /absolute/key --yes
burrow --workspace /absolute/workspace close gateway
burrow --workspace /absolute/workspace close gateway --yes

Normal frontend quit retains the module and master. A lost connection requires explicit reconnect with the desired arguments; inspect and reuse never fall back to a fresh login. Reconnect can replace only a lost connection whose retained owner can still verify and clean its resources. Module loss may leave an unidentified reservation, displayed as lost with its socket path and no retained owner. It requires manual investigation; close and reconnect cannot adopt it. Daemon loss makes workspace state unverified.

Names contain 1–24 ASCII letters, digits, underscores or hyphens, starting with a letter or digit. For canonical workspace W, the socket is W/burrow/NAME/master. Burrow validates the final 90-byte socket-path limit before mutation and atomically reserves the owner-only 0700 directory. The same name can exist in different workspaces. Existing reservations, symlinks, unsafe permissions, replaced roots and unidentified masters are refused without adoption or force deletion.

TUI close NAME shows one exact-target confirmation and refuses a changed owner after review. CLI close retains its explicit review/repeat contract; close NAME --yes avoids duplicate approval. Close reviews the current endpoint, state, master and socket, terminates the owned master, and removes only verified runtime files and the empty reservation. It retains host trust, saved data and Hovel evidence. Unknown leftover files produce a cleanup error and remain in place; the control session is retained for investigation. Broader remote-process containment and automatic stale-resource recovery remain outside this slice.

Terminal controls

Use the same commands inside the TUI. The active table refreshes from retained owners. Tab accepts contextual command/option completion; arrow keys select names or history; F1 opens help; arrow keys scroll help; Escape restores the draft. Alt+Up/Down scroll the bounded connection inventory; overflow labels show the visible range. PgUp/PgDn scroll command output. The center and sidebars shrink at narrow widths without a blocking resize notice. NO_COLOR and --no-color retain labels and keyboard navigation. Ctrl+P opens the searchable Huh Menu inside the retained Menu ///////// banner and colored rounded borders. Quit uses the same default “Keep working” confirmation from commands, shortcuts, Menu and mouse: daemon resources remain, while frontend-local terminals end. New/Open Workspace accepts an exact canonical destination with inline validation and shows launch or refusal state. Typed key, SSH config, known-hosts and workspace paths remain first-class; Ctrl+O or Browse paths opens an optional local Huh file/directory picker. Escape returns to typed input. New workspace destinations need not exist. Browsing reads directory metadata, never key contents.

Disposable acceptance lab

aspect burrow ssh-smoke

During iteration, run the affected portable test through Aspect. aspect burrow ssh-smoke reuses the disposable lab for key authentication, unknown-host refusal/explicit trust, retained owner reuse, duplicate-name refusal and explicit close. It reports stage timings and releases the build server during execution. It intentionally omits the full password/agent/jump/PTY/failure matrix and does not replace ssh-check or the full gate. Full runs also report stage timings so further optimization can follow measured costs.

The controlled gate runs the production command, verified Hovel daemon, retained module and real local OpenSSH client against one disposable OpenSSH Docker container. Docker access and the host OpenSSH client tools are prerequisites; an operator server is not. The server image is declared in core/connection/lab-image.txt, pinned to Linux amd64 manifest sha256:47f82202bcbffe214cea77dc7f5ed24b875e81ce6ebf0e0368e2954727bf5116, resolved from LinuxServer's OpenSSH image on 2026-09-12. See its upstream configuration documentation and source and license. The test generates unique keys, publishes a random loopback port and removes its container and temporary resources.

Checks cover password/encrypted-key/key/agent authentication; aliases and explicit jumps; unknown-host rejection/approval and changed keys on both hops; failed passwords, missing keys/agents and cancellation; guided review and narrow no-color input; secret canaries across process arguments, terminal output and workspace persistence; loss/reconnect, workspace isolation, unsafe-resource refusal, process/socket identities, retained logs, evidence and cleanup uncertainty. Real TUI guided entry, named one-liners, password entry and encrypted-key cancellation check the retained backdrop, alternate-screen ownership and terminal restoration. The portable gate includes setup, command validation and retained proofs; the full gate adds Docker SSH acceptance. The earlier transport proof remains runnable separately and keeps its historical host-binary prerequisites.

The public Hovel CLI installs the immutable cached base Burrow module and owns throw planning/confirmation. Burrow validates the pinned daemon before and after those CLI calls and explicitly selects its existing endpoint, preventing automatic daemon startup. Session operations use a verified Unix peer without implicit redial. These checks do not establish race-free protection against a hostile process running as the same user. SDK stdout is exclusively framed JSON-RPC; connection diagnostics stop after 200 milestones plus one suppression warning, preserving the accepted workaround for Hovel's retained-log ceiling.
