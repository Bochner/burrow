Named SSH connections

Burrow manages a real shell-free OpenSSH master through the single burrow@0.1.0 public-SDK Hovel module. The CLI and Catppuccin terminal interface share the same commands. The connection lifecycle in issue #45 and authentication baseline in issue #46 establish actual SSH access in MVP 1. Interactive shells and tunnels follow in MVP 2; Saved profile collections preserve recipes for later sessions; transfers remain a separate ticket.

One public module

Setup installs only burrow@0.1.0. One ordinary retained session per workspace, kind burrow-manager-v1, owns its SSH masters. The first approved connect activates it with a real confirmed throw; each connect uses another confirmed throw whose short-lived adapter forwards an immutable request to the exact owner. Public setup RPC replaces repeated setup CLI launches; each request keeps an isolated operation/chain so frontends cannot overwrite one another. Hovel retains plans, confirmations and run evidence. List and selected close use bounded session controls, not new throws. Saved-profile management retains the same module’s command input and danger allowance.

Existing workspaces and earlier owners

Opening an existing workspace installs/updates the base module without terminating existing owners or rewriting old chains. Compatibility recognizes retained per-connection sessions from earlier burrow@0.1.0 and burrow-connection@0.1.0 binaries: use the normal connections, inspect, profile save and reviewed close commands. New connects use the base module. Name reservations prevent duplicate creation; unavailable owners or unknown reservations still require manual investigation. This compatibility does not register or relaunch the old module. The retired connection-module entry point refuses new invocations with transition guidance.

Old cached executables and catalog entries may still launch old chains until you retire those submissions. Use session list --json in the workspace’s Hovel CLI to identify sessions whose moduleId is burrow-connection@0.1.0; match their names/session IDs to Burrow’s connection inspection. To finish transition, stop all legacy chain submissions, inspect and explicitly close every old owner when its resources are no longer needed, then use the workspace’s Hovel CLI to run module uninstall burrow-connection@0.1.0. Do not uninstall while old owners are needed. Use Burrow’s reviewed connect path for new connections. The old connection-JSON module input now refuses with migration guidance. Unknown manager kinds are refused; keep their original binary available for explicit cleanup. Updating a catalog never reinterprets a retained process as the new manager. Preserve historical chain configuration, runs, saved profiles, trust and collected evidence; setup never deletes or silently rewrites them. If owner identity or cleanup is uncertain, leave the registration and runtime intact for investigation. Prototype/research module names are historical proof fixtures, not production installation choices.

First select and launch a verified workspace. Connection commands never start a replacement daemon. The required fields are name, host and user; - selects the configured SSH username. Options may appear before, between or after positional fields: --key PATH, --agent PATH, --port NUMBER (SSH config or 22), --ssh-config PATH (default ~/.ssh/config), --jump [USER@]HOST[:PORT][,...], --review HASH (bind a repeated command to its exact recap), --prompt, and --yes. Quote paths containing spaces. The default agent socket comes from the frontend's SSH_AUTH_SOCK and must be accessible to the daemon. Hovel does not refresh its environment when an agent is started or changed later; select the current socket through the frontend's environment or --agent.

Only bare connect opens guided entry: a single editable form followed by resolved review, authentication and an observed result. Fields and named-command suggestions follow LazySSH order: host/IP, port, username, connection name, then optional settings. Example placeholders explain each input; Up/Down, Tab/Shift+Tab or a click selects a field in the TUI. Smaller terminals scroll the form to retain the focused field. Complete commands still accept flags in any order. Argument-bearing incomplete commands report validation errors; complete commands keep their one-line workflow. TUI forms stay in the centered, dimmed management popup. Passwords and encrypted-key passphrases use hidden Huh input over the private authentication transport. Escape or Ctrl+C cancels the active form or attempt, leaving management visible while cleanup completes.

Confirmations default to rejection: Tab or Left/Right chooses, Enter confirms, and Escape cancels. A TUI connect without --yes asks for operation approval; --yes skips that approval but never Hovel’s throw planning and launch-key constraints. CLI commands remain noninteractive unless bare connect or --prompt requests forms. CLI forms read and render on the controlling terminal, preserving redirected JSON stdout and restoring terminal modes after cancellation. Authentication has a two-minute limit and three password attempts. Secrets never become command arguments or review values.

Named command compatibility

connect -ip server.example -port 22 -user ubuntu -socket gateway -ssh-key "/absolute/key with spaces" --yes

The same syntax works after burrow --workspace PATH. The mapping follows pinned LazySSH command source and command tests: -socket supplies the connection name, -ip the host or alias, -user the username, -port the port, and -ssh-key the key path. Unlike LazySSH, the port may use SSH config/22 and the socket path remains workspace-owned. Duplicate fields, including aliases such as -ssh-key with --key, are refused. -proxy, -shell and -no-term are explicitly unsupported; adding forms does not implement tunnels or interactive shells. Bracketed paste edits the command without executing embedded newlines.

Interactive success means the owner verified the master socket. Failed or cancelled interactive attempts close only their exact connection creation and reservation, preserving the manager and siblings; cleanup uncertainty is reported and unknown files remain untouched. Noninteractive --yes registers an asynchronous attempt: inspect its connecting, connected or lost state. A failed asynchronous attempt remains owned until explicit close or reconnect. Hovel records the launch plan and confirmation through its ordinary dangerous-operation and launch-policy flow, in a distinct burrow-* operation with a request chain per attempt.

After successful interactive authentication, Burrow offers to save reusable settings. See saved connection collections for the automatic JSON template, saving an active connection, selecting files, backup and reopen examples.

Aliases and jump hosts

burrow --workspace /absolute/workspace connect gateway my-ssh-alias - --prompt
burrow --workspace /absolute/workspace connect internal target.example ubuntu --jump bastion --prompt

OpenSSH evaluates the operator's trusted local configuration using ssh -G, including Include and Match processing. Match exec remains local executable configuration, so choose configuration you trust. Burrow imports HostName, User, Port, IdentityFile, IdentityAgent and ProxyJump into a private per-connection configuration. Explicit endpoint/key options override the corresponding config values. Multiple identity files and up to eight jump hops are supported; cycles are refused. Each hop uses OpenSSH's native ssh -W forwarding. Burrow supplies the same host-trust policy to all hops; config forwarding, local/remote commands, arbitrary ProxyCommand, host-trust overrides and agent forwarding are not imported. Optional certificate/hardware/MFA customization is outside this baseline.

Host trust

Alias authentication also preserves IdentitiesOnly. A host-specific IdentityAgent (including none) takes precedence over the frontend environment; an explicit --agent takes precedence over both. Jump hosts resolve their own agent settings independently rather than inheriting the target's resolved agent.

The owner selected LazySSH’s -o UserKnownHostsFile=/dev/null -o StrictHostKeyChecking=no policy for the target and every jump hop. There is no separate host-key approval, changed-user-key rejection or user known-host write. Existing trust files are retained but unused. The known-hosts form field, --known-hosts and --trust options, and saved knownHosts setting were removed in issue #73. Old collections containing knownHosts must have that field removed before loading; Burrow does not rewrite existing files automatically.

The single recap displays the exact quoted SSH argv and generated configuration. The TUI scrolls it with ↑↓/PgUp/PgDn while approval controls remain visible; the interactive CLI prints it to terminal scrollback above its single confirmation. Semantic colors preserve the text in NO_COLOR. Interactive submission carries the recap digest; changed settings require another review. Noninteractive clients can repeat the returned digest with --yes --review HASH.

Without an explicit key, OpenSSH selects the current operator’s default files/config/agent. --key '~/path' expands the current home. Host-specific agents and IdentitiesOnly remain supported; account-password fallback follows the resolved authentication settings. Only password/passphrase challenges need additional private input.

OpenSSH askpass answers travel through a short-lived 0700 directory and same-user Unix socket to the requesting frontend, then through an anonymous pipe to OpenSSH. Hovel receives non-secret settings and the temporary endpoint only; passwords, passphrases and private-key contents never enter chain configuration, RPC inputs, histories, artifacts or logging. Direct Hovel automation can use keys/agents; interactive secrets require the live Burrow frontend. This is in-memory credential delivery, not a vault, and does not isolate secrets from a hostile process running as the same user.

Retention, reconnect and close

burrow --workspace /absolute/workspace reconnect gateway server.example ubuntu --key /absolute/key --yes
burrow --workspace /absolute/workspace close gateway
burrow --workspace /absolute/workspace close gateway --yes

Frontend quit lists connections across opened workspaces and asks whether to keep them running or cleanly close them before exit. Escape cancels; Keep running is the safe default when connections exist. Close uses the reviewed owner identity and rechecks remaining resources before exiting; failed cleanup leaves Burrow open with the failure details. Saved profiles, evidence and the daemon remain in either case. A lost connection requires explicit reconnect with the desired arguments; inspect and reuse never fall back to a fresh login. Reconnect can replace only a lost connection whose retained owner can still verify and clean its resources. Manager failure may end every connection in that workspace. Ordinary selected close preserves siblings. Manager loss may leave an unidentified reservation, displayed as lost with its socket path and no retained owner. It requires manual investigation; close and reconnect cannot adopt it. Daemon loss makes workspace state unverified.

Names contain 1–24 ASCII letters, digits, underscores or hyphens, starting with a letter or digit. For canonical workspace W, the socket is W/burrow/NAME/master. Burrow validates the final 90-byte socket-path limit before mutation and atomically reserves the owner-only 0700 directory. The same name can exist in different workspaces. Existing reservations, symlinks, unsafe permissions, replaced roots and unidentified masters are refused without adoption or force deletion.

TUI close NAME shows one exact-target confirmation and refuses a changed owner after review. CLI close retains its explicit review/repeat contract; close NAME --yes avoids duplicate approval. Close reviews the current endpoint, state, master and socket, terminates the owned master, and removes only verified runtime files and the empty reservation. It retains host trust, saved data and Hovel evidence. Unknown leftover files produce a cleanup error and remain in place; the control session is retained for investigation. Broader remote-process containment and automatic stale-resource recovery remain outside this slice.

Terminal controls

Use the same commands inside the TUI. The active table refreshes from retained owners. Tab accepts contextual command/option completion; arrow keys select names or history; F1 opens help; arrow keys scroll help; Escape restores the draft. Alt+Up/Down scroll the bounded connection inventory; overflow labels show the visible range. PgUp/PgDn scroll command output. The center and sidebars shrink at narrow widths without a blocking resize notice. NO_COLOR and --no-color retain labels and keyboard navigation. Ctrl+P opens the searchable Huh Menu inside the retained Menu ///////// banner and colored rounded borders. Quit uses the same connection review from commands, shortcuts and Menu: choose Keep running or Close connections, or Escape to cancel. Use ↑↓/PgUp/PgDn to scroll the complete inventory. Drag selects only the middle panel in either tab. Ctrl+C or Copy copies selected text; Escape clears it, and Ctrl+Shift+V pastes. Nothing copies automatically. Alt+S opts into native terminal selection, which can include sidebars. New/Open Workspace accepts an exact canonical destination with inline validation and shows launch or refusal state. Typed key, SSH config and workspace paths remain first-class; Ctrl+O or Browse paths opens an optional local Huh file/directory picker. Escape returns to typed input. New workspace destinations need not exist. Browsing reads directory metadata, never key contents.

aspect burrow ssh-latency records 20 cold and 20 warm production CLI samples, split between key and private password authentication, followed by separate executable-start traces requiring strace. Setup, submission-to-owner dispatch, submission-to-observed connection and dispatch-to-private prompt are distinct measurements. Traced timings are not latency estimates. The accepted historical one-second/50% cutoffs are not reinstated. The SSH lab separately records list and selected-close completion while a private prompt remains unanswered.

The controlled gate runs the production command, verified Hovel daemon, retained module and real local OpenSSH client against one disposable OpenSSH Docker container. Docker access and the host OpenSSH client tools are prerequisites; an operator server is not. The server image is declared in core/connection/lab-image.txt, pinned to Linux amd64 manifest sha256:47f82202bcbffe214cea77dc7f5ed24b875e81ce6ebf0e0368e2954727bf5116, resolved from LinuxServer's OpenSSH image on 2026-09-12. See its upstream configuration documentation and source and license. The test generates unique keys, publishes a random loopback port and removes its container and temporary resources.

Checks cover password/encrypted-key/key/agent authentication; aliases and explicit jumps; the absence of host-trust prompts and ignored legacy user host records across jumps; failed passwords, missing keys/agents and cancellation; guided review and narrow no-color input; secret canaries across process arguments, terminal output and workspace persistence; loss/reconnect, workspace isolation, unsafe-resource refusal, process/socket identities, retained logs, evidence and cleanup uncertainty. The portable gate includes setup, command validation and retained proofs; the full gate adds Docker SSH acceptance. The earlier transport proof remains runnable separately and keeps its historical host-binary prerequisites.

The public Hovel CLI installs the immutable cached base Burrow module and owns throw planning/confirmation. Burrow validates the pinned daemon before and after those CLI calls and explicitly selects its existing endpoint, preventing automatic daemon startup. Session operations use a verified Unix peer without implicit redial. These checks do not establish race-free protection against a hostile process running as the same user. SDK stdout is exclusively framed JSON-RPC; manager diagnostics share a lifetime budget of 200 milestones plus one suppression warning, preserving the accepted workaround for Hovel's retained-log ceiling.
