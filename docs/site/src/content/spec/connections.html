Named SSH connections

Burrow manages a real shell-free OpenSSH master through a retained public-SDK Hovel module. The CLI and Dracula terminal interface share the same commands. This implements the connection-lifecycle slice in issue #45; profiles, password prompts, SSH configuration aliases, jump hosts, tunnels, interactive shells and transfers remain separate MVP tickets.

Connect and inspect

burrow --workspace /absolute/workspace status
burrow --workspace /absolute/workspace connect gateway server.example ubuntu --key /absolute/key
burrow --workspace /absolute/workspace connect gateway server.example ubuntu --key /absolute/key --yes
burrow --workspace /absolute/workspace inspect gateway
burrow --workspace /absolute/workspace connections

First select and launch a verified workspace. Connection commands never start a replacement daemon. Required connection arguments come first: name, host and user. Options follow: --key PATH, --agent PATH, --port NUMBER (22 by default), --known-hosts PATH, --trust SHA256:FINGERPRINT, and --yes. The default agent is the frontend's SSH_AUTH_SOCK. A key must be unencrypted or usable through an already unlocked agent. No password or passphrase belongs in a command, history or Hovel configuration.

Without --yes, connect and close display a review. With confirmation, connect registers an asynchronous attempt: a successful command response does not alone mean authentication succeeded. Inspect the owner's connecting, connected or lost state, endpoint, module/master PIDs, socket path and inode. Hovel records the launch plan and confirmation through its ordinary dangerous-operation and launch-policy flow, in the burrow operation with a distinct chain per attempt.

Host trust

Existing trust comes from the selected OpenSSH known-hosts file (default ~/.ssh/known_hosts) and private W/burrow-known_hosts. Known hosts are verified directly by OpenSSH. Unknown hosts produce discovered public-key fingerprints without authentication. Verify a fingerprint through an independent trusted channel, then explicitly reconnect the refused attempt with --trust SHA256:FINGERPRINT --yes. Discovery alone is not identity verification.

An approval appends public host-key data to the workspace trust file. That file survives connection close. Changed or revoked keys are refused, including when --trust is supplied. Burrow does not silently update trust, use insecure host-key options, or forward SSH banners and raw authentication diagnostics into logs or the terminal.

Retention, reconnect and close

burrow --workspace /absolute/workspace reconnect gateway server.example ubuntu --key /absolute/key --yes
burrow --workspace /absolute/workspace close gateway
burrow --workspace /absolute/workspace close gateway --yes

Normal frontend quit retains the module and master. A lost connection requires explicit reconnect with the desired arguments; inspect and reuse never fall back to a fresh login. Reconnect can replace only a lost connection whose retained owner can still verify and clean its resources. Module loss may leave an unidentified reservation, displayed as lost with its socket path and no retained owner. It requires manual investigation; close and reconnect cannot adopt it. Daemon loss makes workspace state unverified.

Names contain 1–24 ASCII letters, digits, underscores or hyphens, starting with a letter or digit. For canonical workspace W, the socket is W/burrow/NAME/master. Burrow validates the final 90-byte socket-path limit before mutation and atomically reserves the owner-only 0700 directory. The same name can exist in different workspaces. Existing reservations, symlinks, unsafe permissions, replaced roots and unidentified masters are refused without adoption or force deletion.

Close reviews the current endpoint, state, master and socket, terminates the owned master, and removes only verified runtime files and the empty reservation. It retains host trust, saved data and Hovel evidence. Unknown leftover files produce a cleanup error and remain in place; the control session is retained for investigation. Broader remote-process containment and automatic stale-resource recovery remain outside this slice.

Terminal controls

Use the same commands inside the TUI. The active table refreshes from retained owners. Tab accepts completion; arrow keys select names or history; F1 opens help; arrow keys scroll help; Escape restores the draft. Alt+Up/Down scroll the bounded connection inventory; overflow labels show the visible range. PgUp/PgDn scroll command output. Quote paths containing spaces. Small windows use compact connection rows; below 24 columns or 16 rows, a resize prompt preserves quit controls. NO_COLOR and --no-color retain labels and keyboard navigation. Help, draft editing and normal quit remain responsive during a command.

Disposable acceptance lab

aspect burrow check
aspect burrow ssh-check
aspect burrow-check ci
aspect burrow-check

The controlled gate runs the production command, verified Hovel daemon, retained module and real local OpenSSH client against one disposable OpenSSH Docker container. Docker access and the host OpenSSH client tools are prerequisites; an operator server is not. The server image is declared in core/connection/lab-image.txt, pinned to Linux amd64 manifest sha256:47f82202bcbffe214cea77dc7f5ed24b875e81ce6ebf0e0368e2954727bf5116, resolved from LinuxServer's OpenSSH image on 2026-09-12. See its upstream configuration documentation and source and license. The test generates unique keys, publishes a random loopback port and removes its container and temporary resources.

Checks cover key/agent authentication, trust refusal and approval, cancellation, loss and explicit reconnect, workspace isolation, unsafe-resource refusal, real process/socket identities, retained logs beyond Hovel's notification ceiling, evidence and credential handling, cleanup uncertainty, and actual TUI input/rendering/quit retention. The portable gate includes setup, command validation and retained proofs; the full gate adds Docker SSH acceptance. The earlier transport proof remains runnable separately and keeps its historical host-binary prerequisites.

The public Hovel CLI installs the immutable cached connection module and owns throw planning/confirmation. Burrow validates the pinned daemon before and after those CLI calls and explicitly selects its existing endpoint, preventing automatic daemon startup. Session operations use a verified Unix peer without implicit redial. These checks do not establish race-free protection against a hostile process running as the same user. SDK stdout is exclusively framed JSON-RPC; connection diagnostics stop after 200 milestones plus one suppression warning, preserving the accepted workaround for Hovel's retained-log ceiling.
