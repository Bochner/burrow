Embedded Hovel CLI

Select Hovel in the top bar to start its interactive CLI in the current workspace. The center becomes a terminal; workspace navigation, New/Menu and right metadata remain available. Selecting Burrow restores the overview, prompt draft and scroll position. Each workspace keeps its own CLI tab and pending Hovel prompts; background output continues while another tab is selected.

Controls

Alt+B switches to Burrow and Alt+H opens or returns to Hovel in the current workspace, preserving both tabs' state. These shortcuts work inside the CLI but do not bypass open dialogs. Ctrl+B and Ctrl+H retain their text-editing behavior.

Inside the CLI, keys belong to Hovel unless text is selected: Ctrl+C copies the selection and Escape clears it. With no selection, Ctrl+C interrupts the CLI as usual. Ctrl+] returns focus to Burrow's frame controls. Then use Ctrl+P for the searchable menu, or F6 and arrows to select navigation controls. Open Hovel CLI and Close Hovel CLI are menu actions. Click Hovel or press Enter with that tab selected to return terminal focus. Drag selects only the middle panel in both tabs, even when the pointer crosses a sidebar. Ctrl+C or the visible Copy button copies the selection; Escape clears it. The selected page stays still while background output continues. Highlighting and releasing the mouse never copy automatically. Ctrl+Shift+V pastes; Ctrl+Shift+C also copies if the terminal forwards that key. Copy uses an available Linux clipboard tool (wl-copy, xclip or xsel), falling back to the terminal OSC 52 protocol. The fallback reports “Copy sent to terminal” because terminals may reject clipboard access. Alt+mouse passes through to Hovel applications. Alt+S switches to native terminal selection, which can include sidebars; press it again for panel-only selection. The menu also exposes that toggle.

Closing the CLI ends its frontend-owned process. It does not shut down Hovel or close daemon-owned resources. Burrow quit lists observed connections across all workspaces opened in this frontend. Keep running leaves them retained; Close connections uses reviewed, verified teardown before exit; Escape cancels. Failed cleanup stays visible and keeps Burrow open. Both exit choices end frontend CLI processes and retain the daemons. Closing an active client is not proof that a daemon-owned throw was cancelled: inspect Hovel's throw and session history before repeating work. Hovel session attachments follow Hovel's own attachment semantics; these are distinct from shared SSH shells.

An exited or refused tab remains visible. Selecting it does not launch again. Click Restart CLI in the pane, or press Ctrl+R while focused there, to explicitly start a fresh CLI. The old process is reaped first; commands are never replayed. Closing the tab and opening Hovel CLI also remains available. A missing or stale daemon is refused; restarting the CLI cannot restart the daemon.

The top-right Daemon: connected indicator reports a fresh successful check of the workspace daemon, independently of the embedded CLI. Typing quit or exit ends only the CLI: its pane reports CLI: exited, while a reachable daemon remains connected.

Known resize limitation: the pinned emulator clips existing output rather than reflowing it. After shrinking and growing the pane, truncated lines or old wrapped prompt fragments can remain until Hovel redraws. Pane dimensions and cursor coordinates update, but Burrow does not inject redraw keystrokes: those could reach a pending confirmation.

Runtime and terminal compatibility

Burrow verifies its pinned Hovel v0.4.2 executable and workspace before invoking shell --workspace /canonical/path with an explicit HOVEL_DAEMON_ENDPOINT=/canonical/path/hoveld.sock. Inherited HOVEL settings are removed using the same policy as one-shot operations. The verification timeout does not limit the interactive process. Hovel owns parsing, plans, review, confirmation, launch-key policy, history and audit. Burrow neither answers prompts nor stores a terminal transcript.

One Bubble Tea program owns the physical terminal. The existing pinned Charm x/vt emulator consumes each Linux PTY; Burrow renders its screen and clipped cursor only in the center. Terminal replies use pane coordinates, and mouse input reaches the child only inside that pane and for supported mouse modes. Existing Ultraviolet types bridge input without a second event loop or a dependency upgrade. Geometry is bounded to 1–1000 cells per axis. The pinned emulator uses legacy xterm keyboard encoding; Kitty key release/extended-key protocols are not advertised. Unbracketed pasted newlines become spaces so paste cannot submit commands implicitly.

The declared checks cover terminal input, output, alternate screens, cursor replies, geometry, process cleanup, persistent frame controls and the real pinned CLI in isolated workspaces. The CLI acceptance uses the harmless Burrow workspace-inspection module through Hovel's own review and confirmation flow. These checks do not establish SSH-shell parity.
