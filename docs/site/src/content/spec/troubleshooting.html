Troubleshooting

Keep the exact command, workspace, returned resource ID and error. Review and submission are not proof of execution. Inspect an uncertain operation before repeating it; a new run now, survey or chain throw can execute the work again.

Installation and startup

SymptomNext step
Unknown capabilities, workspace, follow or agent commandCheck burrow --help and the executable you launched. Those commands are in current source, beyond v0.1.0. See the version table.
Pinned Hovel package is not cachedRun normal setup online, or supply the exact wheel with --hovel-package FILE. A fresh cache alone cannot satisfy --offline.
Checksum mismatch or .pending cache reservationPreserve the reported path and inspect an interrupted or changed install. Repeating launch will not adopt it; there is no checksum override.
Unsafe directory, symlink or socket path too longUse a canonical private workspace under a trusted parent. Connection sockets must fit the 90-byte path limit; select a shorter workspace path when necessary. Do not weaken permissions to bypass refusal.
TUI requires terminal inputRun in a real terminal. Use status for release-compatible JSON setup, or current-source workspace inspect for read-only verification.

Setup logs are retained in WORKSPACE/burrow-launch.log. Receipts, socket/process identity and ownership checks protect existing resources. Burrow refuses an unknown runtime root, daemon lock/status, stale receipt or replacement socket.

Unknown, lost or older owners

  1. In current source, run burrow --workspace PATH workspace inspect. If the daemon cannot be verified, stop resource mutations and preserve the launch log, receipt and workspace.
  2. With a verified daemon, use connections, inspect NAME, transfers and run inspect ID. Failed observation means unverified, not an empty inventory.
  3. For an older live manager, review restart or retirement only when ending all its connections is intended. The command does not restart Hovel or recover a crashed daemon.
  4. For unknown ownership or a lost daemon, investigate the reported path and associated process/socket identity before manual recovery. Failure to connect does not prove a process is dead or that files are safe to remove.

There is no force-delete, automatic restart, resource adoption or automatic reconnect. Preserve saved settings, collected artifacts and unknown files. The known Hovel SQLite limitation can interrupt active work; database is locked, daemon loss and completion uncertainty must remain distinct outcomes.

Authentication and forwarding

SymptomNext step
Connecting never becomes connectedInspect the exact creation. An asynchronous launch can fail after the CLI returns. For private challenges use guided connect, --prompt or bare --password.
Key or agent not acceptedCheck the resolved user, key/config path and accessible agent socket. Without an explicit key Burrow uses current-user OpenSSH selection. A key file's existence does not establish successful authentication.
Password field is visible in the TUIOrdinary TUI authentication uses the owner's visible-entry preference. Bare --password and chain authentication use hidden fields; CLI secret prompts are hidden. See authentication.
Listener exists but traffic failsCheck the service from the correct side, destination and server forwarding permissions. A bound listener does not establish application health. See forwarding.
Saved chain refuses after upgrade or recreationInspect the build and complete creation IDs, then explicitly re-export. A reused connection name or port is not the original resource.

Files, output and reports

SymptomNext step
Upload or script path refusedUse local to find the configured upload root. Place a regular file inside it and use a relative path. The process working directory is not an upload fallback.
Transfer failed or was cancelledRead transfers ID and the per-file result. Existing destinations survive interrupted replacement; labelled partials can remain. Retry selected failures with a fresh review; copying restarts at zero.
Command returned success but the target command failedRead remoteExit or localExit, capture completeness and collection separately. A recorded result can have a nonzero command exit.
Collection failedRetry run collect ID for the same retained run. Do not prepare another run merely to recover output.
Output or report unavailable after lossCheck Hovel's registered artifacts. Uncollected output has no recovery guarantee; unknown working files are not proof of complete capture.
Ctrl+N/Ctrl+L or profile editor unavailableInstall local Vim with syntax/runtime support. Use CLI run output/report commands where appropriate; Burrow does not download an editor.

The script cleanup guide, chain troubleshooting and skill discovery/update guidance cover their specific limits. The website's Reports page describes CI evidence, not missing operational reports in your workspace.
