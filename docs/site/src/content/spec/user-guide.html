Start here

Burrow manages SSH connections, shells, forwarding, files and retained commands from a Linux terminal. Hovel keeps workspace state and collected evidence; Burrow installs and starts its pinned Hovel dependency for you.

Which version does this book describe?

This book follows the current source. The v0.1.0 development release contains MVP 1–4 and is distributed as source, with no attached binary assets. The repository currently requires access. Follow Install and launch to build it.

Your first connection

  1. Build and install Burrow, then open a private workspace: burrow --workspace "$HOME/burrow-lab".
  2. In the Burrow management prompt, enter connect. Fill in the host, account and connection name. Port, key and agent settings can use their defaults.
  3. Review the actual SSH command and resolved settings, then confirm. Complete authentication if asked. Wait for connected; an accepted launch alone is not authentication success.
  4. Optionally save the successful connection's settings when offered. Saved profiles contain references and preferences, never passwords or private-key contents.
  5. Enter shell gateway, replacing gateway with your connection name. Ctrl+] returns to management and releases your control while retaining the shell. Resume observes; Alt+T explicitly takes control.

Host trust follows the accepted LazySSH policy: StrictHostKeyChecking=no and UserKnownHostsFile=/dev/null. There is no separate host-key approval or retained user host-trust record. Read the authentication guidance before connecting.

Reference and evidence

The API tab is generated from burrow capabilities: supported commands, inputs, results and known interface gaps. The website Reports tab contains CI tests, production coverage and operator parity. Neither is the reports command, which reads operational Markdown evidence collected in your workspace.

Legacy LazySSH plugins, server deployment, additional OS surveys, SMB and WinRM are outside the implemented workflows. See Hovel integration for ownership and the development guide for builds and checks.
