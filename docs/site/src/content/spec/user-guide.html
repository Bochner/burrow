User guide

The API reference lists current CLI and human routes, inputs, results, approval rules and unsupported paths. Run burrow capabilities for the same machine-readable contract without opening a workspace or TUI; burrow capabilities run.output selects one capability.

For Hovel-driven SSH connections, including running Dropbear servers, and reviewed HTTP through existing tunnels, see the visual SSH and tunnel chains walkthroughs for Burrow's TUI, shell CLI and embedded Hovel CLI.

Burrow is the Go successor to LazySSH. The production Linux amd64 package supports verified Hovel workspaces, retained SSH connections, saved settings, interactive shells, forwarding, file transfers, commands and scripts, live output, local automation, Ubuntu reports and Hovel chains. MVP 1–4 are implemented; MVP 5 covers operator skills and final daily-use acceptance. Start with the setup and launch guide.

Connect and save settings

The connection guide covers passwords, encrypted keys, SSH agents, SSH config aliases and jump hosts. Host trust uses the owner-selected LazySSH settings, StrictHostKeyChecking=no and UserKnownHostsFile=/dev/null, with no separate host-key approval. After successful interactive authentication, Burrow offers to save the settings for a future session.

Each workspace automatically receives a private burrow-profiles.json template with instructions and an inactive example. Follow saved connection collections for a filled-out JSON example and commands to create, save, edit, delete, load and back up profiles. Opening a collection only displays settings; connect explicitly when ready.

Connection lifetime

Quit reviews whether to keep connections running or close them, while retaining the daemon. Frontend-local shells end on exit. Reopen the same workspace to manage retained connections, or use close NAME to review and end one. Editing or deleting a saved profile changes future connections only. Saved settings contain no passwords or private-key contents.

Follow the work

scp NAME enters file browsing and transfers through a live connection, with remote navigation, cached completion and persistent workspace upload/download roots. Download with get or mget, upload with put, and review retained outcomes with transfers.

Use shell NAME to open an interactive SSH shell through a live connection. Ctrl+] backgrounds it; open another, list with shells, return with resume ID, or close one with shell-close ID. Shells share the owning connection's master socket. The forwarding guide covers local and reverse listeners.

Run commands and scripts

To inspect an existing connection through Claude Code, Codex or OpenCode, install the Burrow operator skills with burrow agent install CLIENT --scope user|project. The bundled skills use the same CLI review, output and evidence contracts.

Enter these examples in the management prompt for a live connection named gateway. The first runs an existing command. The second streams a local script from the configured upload root:

run now gateway -- ps -elf
run now gateway --script check.sh --mode stream --interpreter /bin/sh --

Review and confirm to execute and collect. Press Ctrl+L to read stdout, stderr and the outcome. The TUI walkthrough and worked script examples explain where files belong, literal arguments, independent stdin, inline and staged modes, timeouts, keep and cleanup. run list and run inspect ID expose retained state after you leave the view.

run follow ID opens an independent live stdout/stderr viewer; closing it leaves the run active. Use --local to run a selected local tool with non-secret connection context. Both share the reviewed run lifecycle; local tools and automation explains local exit and cancellation limits.

Use run survey CONNECTION --os ubuntu for a reviewed inventory survey and reports to read its saved Markdown in an independent view. See Ubuntu surveys and reports.
