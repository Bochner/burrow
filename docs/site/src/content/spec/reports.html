Ubuntu surveys and reports

These are operational Markdown reports collected in your workspace. The website Reports tab instead shows CI tests, coverage and operator parity; the API tab documents command contracts.

Run a small inventory survey on an existing connection, then open its saved report inside Burrow:

run survey ubuntu-test --os ubuntu
reports

Replace ubuntu-test with your live connection name. Review the target, command set, timeout, output budget and script hash, then confirm. This launches the prepared run once, waits, and saves its Markdown report. reports opens an independent browser; it is also available in the Ctrl+P menu. Ctrl+L retains its existing Collected output and Activity log editors.

The Ubuntu preset

--os ubuntu is required and is the only implemented preset. Its fixed read-only commands run as the connected account through /bin/sh. It does not use sudo, install packages, upload a script, discover credentials or scan other hosts. It records UTC observation time, OS release, hostname, kernel/architecture, current identity/groups, uptime, load, memory, filesystem capacity, network addresses/routes, listening TCP/UDP sockets and failed services.

Each probe uses the target's timeout utility with a five-second KILL timeout. Missing utilities are UNAVAILABLE; nonzero exits are FAILED with their returned output. The coverage footer counts observed, failed and unavailable checks. Exit 1 means at least one check failed or was unavailable. Other Linux userlands, including the disposable SSH lab, remain explicitly unverified. These are raw inventory observations, not vulnerability findings or proof of host health.

The preset defaults to a 90-second run timeout and 1 MiB per output stream. Optional --timeout DURATION and --budget BYTES override them. Run-level timeout and cancellation use the existing retained-run lifecycle; remote cleanup uncertainty remains visible. Output limits or write failures leave an INCOMPLETE CAPTURE report with collectible partial bytes. Completed capture and successful checks are separate outcomes.

Saved evidence and recovery

Confirmation includes execution and saving. The survey keeps the existing stdout, stderr and JSON result artifacts and adds Markdown plus versioned report metadata. Hovel owns storage, timestamps, identifiers and SHA256 digests. The report records producer, connection/endpoint, source run, execution exit, capture completeness and any capture error. It survives run close, connection close and frontend exit.

If collection fails, inspect the returned run ID and retry run collect ID. Do not repeat the survey merely to recover a save: that would execute another run. Repeated collection creates a separate inventory entry for the same observations. Closing an uncollected run can lose its report.

The reader opens only registered workspace artifacts, checks their private regular-file ownership and SHA256, and refuses missing, replaced, symlinked, unreadable or oversized documents. Its Markdown limit is 1 MiB; larger originals remain stored at the artifact path. Unsupported or damaged metadata remains visible as an unavailable report. Raw and encoded terminal controls are escaped for display; OSC hyperlinks are removed. Allowed presentation styling uses the shared Catppuccin roles. Original artifact bytes are unchanged.

CLI and automation

burrow --workspace /absolute/workspace run survey ubuntu-test --os ubuntu
# Review the response, then run its exact confirm command with this workspace.
burrow --workspace /absolute/workspace reports
burrow --workspace /absolute/workspace report REPORT_ID

Shell CLI output is JSON, with syntax coloring on a terminal. reports lists saved metadata; report ID returns metadata and Markdown text. The native browser opens from Burrow's management prompt or Ctrl+P menu. Explicit --yes confirms a new survey without an interactive recap. The same commands are available through the single burrow@0.1.0 module's command setting, subject to Hovel's normal confirmation and launch policy.

Report producer contract

The internal core/reports package exposes Artifacts(name, metadata, path), List and Read. A producer returns the two artifacts through its normal public Hovel SDK result: a text/markdown file and application/vnd.burrow.report+json metadata. Version 1 metadata names its Markdown artifact in the same Hovel run and module. There is no additional database, public module, plugin registry or OS adapter framework. Ordinary command output is not automatically treated as a report.
