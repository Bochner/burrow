Interactive SSH shells

After connecting, enter shell NAME in management, or run burrow --workspace /absolute/workspace shell NAME from a terminal. The CLI opens the same management frame with the SSH pane selected. The shell uses the server account's normal login shell through the existing authenticated master; it never connects or authenticates again.

TUI lifetime: shells opened with shell NAME belong to this frontend and end when it exits, including Keep running. Current source also supports the separate headless retained-shell lifecycle below. Shared control and observation are available headlessly; TUI attachment remains follow-on work. See quit, detach and close.

Retained shells from the CLI (current source)

Use session to create, list, inspect and close real SSH shells retained by Hovel. Select an existing connection explicitly. Each shell has an opaque Hovel ID, its own SSH client and remote login shell, and a default initial size of 80×24 (override with --columns N --rows N when creating). Exiting the creating CLI leaves it alive. The commands below provide private controller input, live resize, independent byte reads and current-screen snapshots without requiring a TTY. TUI tabs remain separate.

burrow --workspace /absolute/workspace session create gateway
# Approve the returned review and copy its digest:
burrow --workspace /absolute/workspace session create gateway --yes --review HASH
burrow --workspace /absolute/workspace session list gateway
# Use the returned opaque id, not a TUI shell number:
burrow --workspace /absolute/workspace session inspect gateway ID
burrow --workspace /absolute/workspace session close gateway ID
burrow --workspace /absolute/workspace session close gateway ID --yes --review HASH

Create and close return a review without --yes. --review HASH binds confirmation to the workspace, connection creation, manager generation and observed resource state; changed reviews are refused. Explicit --yes without a hash approves the current selection. Creation prepares an ordinary burrow-shell-v1 Hovel session through a supported throw, then launches it through another confirmed adapter admitted by the existing manager. Existing Hovel launch policy can reject either step. A failed acknowledgement is uncertain: inspect session list CONNECTION before doing anything else. A leftover prepared session has not started SSH; close it explicitly before a new reviewed creation. There is no automatic launch retry.

JSON results include the explicit workspace, id, immutable connection binding, owning-module ownerPID, local SSH pid, lifecycle state, geometry and output counters. The connection binding is the creation snapshot, not current connection health; use inspect CONNECTION for that. running means the local SSH process has started, not that a remote command succeeded. Normal channel exit, including a nonzero shell exit, is exited. sshExit records the local SSH process exit status; 255 or signal termination is lost with an uncertain remote outcome. It does not certify the outcome of individual terminal commands. A missing module is unavailable, with uncertain remote-command outcomes and cleanup. Missing or closed-and-removed IDs refuse inspection; no replacement is adopted. Errors use JSON on stderr and exit 1, with operation: session.ACTION, code: operation_failed and a descriptive message.

The module drains the PTY into a bounded 64 KiB memory suffix independently of viewers. received, buffered and dropped expose its current counters; bytes are not logged or collected as evidence. Raw Hovel send, attach and read cannot provide interactive access: input is rejected and reads expose no terminal bytes. Use the shared commands below to control or observe this terminal. Use retained runs when you need structured command completion, exit status or collected evidence.

Selected close terminates and waits for that shell's owned SSH process and channel, returning final counters and cleanup metadata. Native Hovel close is reconciled from its broker inventory. Audit-write failures report incomplete evidence while confirmed physical cleanup still proceeds; an inspectable closed record retains auditError until explicitly removed. It preserves the master, sibling shells, tunnels and transfers; remote command outcomes and escaped descendants remain unconfirmed. Reviewed connection close includes every admitted dependent shell, and a new shell invalidates an earlier connection review. Manager retirement includes concurrent additions. Missing acknowledgements, replaced sockets or uncertain ownership refuse cleanup and preserve resources for investigation. Keep running retains these shells, while the existing frontend-local shells still end on exit. Daemon or owning-module loss cannot restore a shell; stale receipts require the existing manual recovery process. Saved settings and collected evidence remain.

Use aspect burrow sessions-check for the focused declared SSH-fixture check. It is included in the production shell partition. burrow capabilities session.create and the generated session API reference describe the current wire shapes. Older retained managers must be explicitly retired before this capability is available.

Control and observe without a TTY

Exactly one controller may send input or resize. session claim CONNECTION ID --request-stdin claims an unowned shell. session takeover requires the controlGeneration most recently observed by session inspect; competing takeovers cannot both succeed. Claim/takeover accept an optional label (default agent) and columns/rows (omitted dimensions preserve the current size). Dimensions must each be 1–1000 with at most 20,000 total cells; zero, null and invalid input are refused by the real shell owner.

All five control commands require one JSON object on piped/file stdin and piped/file stdout. Keep the returned token in memory, or protect any deliberately retained request file with mode 0600. Never paste it into argv, shell history, logs, activity, or evidence. The label is descriptive, not proof the client is still alive. A disappeared process leaves its claim until explicit takeover; no lease expires automatically. Release invalidates its token and preserves the remote shell, working directory and last geometry.

import base64, json, subprocess
workspace, connection, session = "/absolute/workspace", "gateway", "SHELL_ID"
base = ["burrow", "--workspace", workspace, "session"]

def call(action, request=None):
    args = base + [action, connection, session]
    if request is not None:
        args += ["--request-stdin"]
    result = subprocess.run(args, input=json.dumps(request) if request is not None else None,
                            capture_output=True, text=True, check=True)
    return json.loads(result.stdout)

claim = call("claim", {"label": "maintenance", "columns": 100, "rows": 30})
try:
    accepted = call("input", {"token": claim["token"],
                             "data": base64.b64encode(b"pwd\n").decode()})
    # acceptedBytes is input acceptance, never command completion.
    screen = call("snapshot")  # Poll again for later output; do not infer exit status.
    call("resize", {"token": claim["token"], "columns": 120, "rows": 40})
finally:
    call("release", {"token": claim["token"]})

For takeover, inspect first, then call takeover with {"label":"operator","generation": observed["controlGeneration"]}. It returns a new token. Delayed input, resize and release using the old token are refused. Do not automatically retry an uncertain claim, takeover or write: inspect controller state first. input accepts 1–4096 decoded bytes; Ctrl+C is the byte 0x03 (base64 Aw==). Under backpressure, acceptedBytes is the accepted prefix and backpressure is true; the remaining suffix was not accepted. Other PTY write failures return inputError with the same accepted-prefix rule. This never establishes what the remote application executed.

Independent reads and recovery

burrow --workspace /absolute/workspace session observe gateway SHELL_ID
burrow --workspace /absolute/workspace session observe gateway SHELL_ID NEXT_OFFSET
burrow --workspace /absolute/workspace session snapshot gateway SHELL_ID

Each observer owns its own byte position (default 0). observe returns base64 data, oldest, next, gap, closed, lost and shell metadata. Reading never consumes another reader's output, claims control or resizes. If a position falls behind the 64 KiB suffix, the result stays out-of-sync, returns no bytes, and leaves next at the requested position. Moving to a newer position cannot reconstruct a screen.

Recover with snapshot: it returns the owner's complete current display, cursor coordinates (zero-based), cursor visibility, alternate-screen flag, geometry and matching byte position. Only a successful snapshot is snapshot-current. Render it as a complete display and poll snapshots for subsequent current views; it is not serialized parser state, so do not feed later byte reads into it as if it were an emulator checkpoint. Byte observations remain labelled stream-only. A conservative 256 KiB cell-content budget is checked before rendering, and snapshots are capped at 256 KiB encoded JSON; an oversized view returns out-of-sync with recoveryError and no screen. Keep the viewer out of sync until a later snapshot succeeds. Closed shells expose their final available view; loss labels any retained view last-known-screen, never live. Explicit removal makes further requests fail rather than inventing a replacement.

The existing pinned Charm VT interprets the screen with no scrollback, separately from bounded byte history. Its parser limit is 4 MiB; geometry, parser and response bounds are not a total-memory or universal-terminal-compatibility guarantee. Resize clips existing contents instead of reflowing them. Snapshots are render-only: they do not inject terminal-query replies; the controller can answer queries through the input route. Remote clipboard/title controls do not reach the observer's terminal. Shell bytes are not collected or logged. Shared-session activity integration remains follow-on work.

Public Hovel session-command route

The CLI uses the existing owner-protected workspace socket and supported RunSessionCommand. Select a burrow-shell-v1 ID from ListSessions. The request is {"SessionID":"ID","Request":{"command":"input","inputEncoding":"utf-8","inputData":"JSON_OBJECT"}}, where the nested JSON contains the token and base64 data. Claim, takeover, resize and release use the same private-input fields and their documented schemas. Observe uses args:["OFFSET"]; snapshot and inspect have no arguments. No token-bearing positional arguments, input paths, config or reconnect fields are accepted. The public result's stdout contains the same JSON object returned by Burrow. These controls arbitrate input; they do not create a security boundary against the workspace's operating-system owner or substitute for confirmed connection creation.

Open, switch and close

Ordinary keyboard input, including Ctrl+C and Ctrl+D, reaches the selected remote terminal. Ctrl+] or Alt+B returns to management while keeping it running. Open more shells with shell NAME, including multiple shells on the same connection. Each shell has its own ID, PTY, screen, cursor, supported input modes and bounded history. Background output continuously updates its screen while management or another shell is displayed. Only the selected view controls input.

shell gateway
# Ctrl+] returns to management
shell gateway
# Ctrl+] returns to management
shells
resume 1
# Ctrl+] returns to management
shell-close 2

shells lists shells in the current workspace of this frontend. resume ID selects one, and shell-close ID closes exactly that shell. Without an ID, shell-close closes the last selected shell; after that shell ends, the most recently opened remaining shell becomes the selection. Numbers are current workspace positions, always 1 through the number of shells: closing a shell renumbers the remaining entries without restarting them. Opening after closing #2 of two creates #2 again. Completion follows the current numbers; they are not permanent resource IDs. A separate Burrow process cannot resume or manage these local shells.

Navigate shells

The left sidebar has workspaces above a midpoint New/Menu row and SHELLS - SSH below. Top workspace selection returns to Burrow management. The lower tree stays expanded, one child row per shell, without summaries or collapsed siblings. When it exceeds its available height, wheel or F6, arrows and Enter reach the remaining rows independently of the upper workspace list. Each shell also has its own clickable top tab. Alt+1–9 selects that numbered shell; Alt+Left/Right cycles through all shells. Narrow tab strips shorten labels and keep the selected tab visible, with arrow controls for overflow. Ctrl+] or Alt+B returns to management without ending the shell. These controls preserve each shell's independent terminal state and reuse the same master connection.

exit or shell close preserves the connection and sibling shells. A background shell exiting does not steal the active view; management reports its ID and outcome. If text is selected, Ctrl+C copies it; Escape clears selection before Ctrl+C can interrupt the remote program. Shell screens are not durable evidence, and existing collected artifacts are preserved.

History and resizing

The Shells sidebar combines local opening/closing/error state with observed connection health. The pane identifies its connection and shell ID and labels output as local and not recorded. Initial and subsequent geometry follow the center pane, including when hidden; resume reapplies current dimensions. Invalid outer geometry is refused visibly while retaining the previous size; new shell launches wait for valid geometry. Shift+PgUp/PgDn scroll history and Shift+Home/End select oldest/live output. Each SSH shell retains at most 1,000 history lines in memory. Closing it discards that history. The screen geometry, history and library parser limits are separate bounds, not a total memory guarantee or a shell-count performance guarantee.

Quit reviews connections across opened workspaces. Keep running preserves daemon-owned connections; Close connections tears down the reviewed connections; Escape cancels. Actual frontend exit ends and reaps all its local terminal clients. Connection-wide close or master loss also ends attached shells. Ending the local SSH client does not prove termination of deliberately detached remote processes. Saved settings and existing artifacts remain intact.

Ownership, older managers and terminal compatibility

All shells on a named connection reuse its single established master socket and SSH transport, including the route chosen when connecting. Opening a shell creates a local multiplexed SSH client and a remote shell process, not another authenticated network connection. The connection-owned SOCKS proxy remains available independently; shells do not create new proxies or connect through SOCKS again.

The shared production command verifies the retained burrow manager, generation, connection creation, runtime reservation and live master. Its public Hovel session command shell GENERATION CREATION returns verified connection metadata only. The frontend checks the socket inode and peer PID before launching an ordinary OpenSSH multiplexed client with a controlling PTY. ProxyCommand=/usr/bin/false prevents a fresh-login fallback if the master disappears. Earlier owners without this command are refused. Quit old frontends and use make restart (defaults to ~/burrow-test; override with WORKSPACE=/absolute/path), or aspect burrow run -- --workspace /absolute/path restart. The Make shortcut passes --yes and retires the old manager without prompting, closing its connections and shells. The plain CLI command still asks for confirmation. Reconnect explicitly afterward. Saved settings, evidence and Hovel remain. make clean only removes build outputs; it cannot replace a retained owner.

PTY bytes and resizing remain frontend-local. They do not use Hovel's session I/O or a Hovel resize API, and are not Hovel-recorded evidence. The same base public module and existing confirmation/logging contracts remain in use. Local shells use the existing pinned Charm VT and Bubble Tea terminal host; no dependency or terminal service was added. Remote OSC clipboard/title requests stay inside the emulator. Burrow's controls retain the Catppuccin theme and no-color/narrow layouts.

This follows LazySSH's native terminal flow and terminal checks: verify a live connection, request a TTY, wait for exit and return to management. Intentional differences are the embedded VT, explicit on-demand launch, local history, and refusal of fallback authentication. Custom shell selection, Terminator and automatic terminal launch on connect are not part of this slice. The pinned VT clips rather than reflows old output on resize; graphics, enhanced keyboard protocols and universal terminal-application compatibility are not claimed.
