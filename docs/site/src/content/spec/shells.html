Interactive SSH shells

After connecting, enter shell NAME in management, or run burrow --workspace /absolute/workspace shell NAME from a terminal. The CLI opens the same management frame with the SSH pane selected. The shell uses the server account's normal login shell through the existing authenticated master; it never connects or authenticates again.

Current-source lifetime: TUI tabs and headless agents attach to the same Hovel-retained SSH shells. A human can observe an agent, explicitly take control, detach and return to the same shell. Keep running retains the shells and releases only this frontend’s control. v0.1.0’s frontend-local lifetime is replaced in current source. See quit, detach and close.

Retained shells from the CLI (current source)

Use session to create, list, inspect and close real SSH shells retained by Hovel. Select an existing connection explicitly. Each shell has an opaque Hovel ID, its own SSH client and remote login shell, and a default initial size of 80×24 (override with --columns N --rows N when creating). Exiting the creating CLI leaves it alive. The commands below provide private controller input, live resize, independent byte reads and current-screen snapshots without requiring a TTY. Use shell CONNECTION ID to observe one in the TUI.

burrow --workspace /absolute/workspace session create gateway
# Approve the returned review and copy its digest:
burrow --workspace /absolute/workspace session create gateway --yes --review HASH
burrow --workspace /absolute/workspace session list gateway
# Use the returned opaque id, not a TUI shell number:
burrow --workspace /absolute/workspace session inspect gateway ID
burrow --workspace /absolute/workspace session close gateway ID
burrow --workspace /absolute/workspace session close gateway ID --yes --review HASH

Create and close return a review without --yes. --review HASH binds confirmation to the workspace, connection creation, manager generation and observed resource state; changed reviews are refused. Explicit --yes without a hash approves the current selection. Creation prepares an ordinary burrow-shell-v1 Hovel session through a supported throw, then launches it through another confirmed adapter admitted by the existing manager. Existing Hovel launch policy can reject either step. A failed acknowledgement is uncertain: inspect session list CONNECTION before doing anything else. A leftover prepared session has not started SSH; close it explicitly before a new reviewed creation. There is no automatic launch retry.

JSON results include the explicit workspace, id, immutable connection binding, owning-module ownerPID, local SSH pid, lifecycle state, geometry and output counters. The connection binding is the creation snapshot, not current connection health; use inspect CONNECTION for that. running means the local SSH process has started, not that a remote command succeeded. Normal channel exit, including a nonzero shell exit, is exited. sshExit records the local SSH process exit status; 255 or signal termination is lost with an uncertain remote outcome. It does not certify the outcome of individual terminal commands. A missing module is unavailable, with uncertain remote-command outcomes and cleanup. Missing or closed-and-removed IDs refuse inspection; no replacement is adopted. Errors use JSON on stderr and exit 1, with operation: session.ACTION, code: operation_failed and a descriptive message.

The module drains the PTY into a bounded 64 KiB memory suffix independently of viewers. received, buffered and dropped expose its current counters; bytes are not logged or collected as evidence. Raw Hovel send, attach and read cannot provide interactive access: input is rejected and reads expose no terminal bytes. Use the shared commands below to control or observe this terminal. Use retained runs when you need structured command completion, exit status or collected evidence.

Selected close terminates and waits for that shell's owned SSH process and channel, returning final counters and cleanup metadata. Native Hovel close is reconciled from its broker inventory. Audit-write failures report incomplete evidence while confirmed physical cleanup still proceeds; an inspectable closed record retains auditError until explicitly removed. It preserves the master, sibling shells, tunnels and transfers; remote command outcomes and escaped descendants remain unconfirmed. Reviewed connection close includes every admitted dependent shell, and a new shell invalidates an earlier connection review. Manager retirement includes concurrent additions. Missing acknowledgements, replaced sockets or uncertain ownership refuse cleanup and preserve resources for investigation. Keep running retains these shells whether created through the CLI or TUI. Daemon or owning-module loss cannot restore a shell; stale receipts require the existing manual recovery process. Saved settings and collected evidence remain.

Use aspect burrow sessions-check for the focused declared SSH-fixture check. It is included in the production shell partition. burrow capabilities session.create and the generated session API reference describe the current wire shapes. Older retained managers must be explicitly retired before this capability is available.

Control and observe without a TTY

Exactly one controller may send input or resize. session claim CONNECTION ID --request-stdin claims an unowned shell. session takeover requires the controlGeneration most recently observed by session inspect; competing takeovers cannot both succeed. Claim/takeover accept an optional label (default agent) and columns/rows (omitted dimensions preserve the current size). Dimensions must each be 1–1000 with at most 20,000 total cells; zero, null and invalid input are refused by the real shell owner.

All five control commands require one JSON object on piped/file stdin and piped/file stdout. Keep the returned token in memory, or protect any deliberately retained request file with mode 0600. Never paste it into argv, shell history, logs, activity, or evidence. The label is descriptive, not proof the client is still alive. A disappeared process leaves its claim until explicit takeover; no lease expires automatically. Release invalidates its token and preserves the remote shell, working directory and last geometry.

import base64, json, subprocess
workspace, connection, session = "/absolute/workspace", "gateway", "SHELL_ID"
base = ["burrow", "--workspace", workspace, "session"]

def call(action, request=None):
    args = base + [action, connection, session]
    if request is not None:
        args += ["--request-stdin"]
    result = subprocess.run(args, input=json.dumps(request) if request is not None else None,
                            capture_output=True, text=True, check=True)
    return json.loads(result.stdout)

claim = call("claim", {"label": "maintenance", "columns": 100, "rows": 30})
try:
    accepted = call("input", {"token": claim["token"],
                             "data": base64.b64encode(b"pwd\n").decode()})
    # acceptedBytes is input acceptance, never command completion.
    screen = call("snapshot")  # Poll again for later output; do not infer exit status.
    call("resize", {"token": claim["token"], "columns": 120, "rows": 40})
finally:
    call("release", {"token": claim["token"]})

For takeover, inspect first, then call takeover with {"label":"operator","generation": observed["controlGeneration"]}. It returns a new token. Delayed input, resize and release using the old token are refused. Do not automatically retry an uncertain claim, takeover or write: inspect controller state first. input accepts 1–4096 decoded bytes; Ctrl+C is the byte 0x03 (base64 Aw==). Under backpressure, acceptedBytes is the accepted prefix and backpressure is true; the remaining suffix was not accepted. Other PTY write failures return inputError with the same accepted-prefix rule. This never establishes what the remote application executed.

Independent reads and recovery

burrow --workspace /absolute/workspace session observe gateway SHELL_ID
burrow --workspace /absolute/workspace session observe gateway SHELL_ID NEXT_OFFSET
burrow --workspace /absolute/workspace session snapshot gateway SHELL_ID

Each observer owns its own byte position (default 0). observe returns base64 data, oldest, next, gap, closed, lost and shell metadata. Reading never consumes another reader's output, claims control or resizes. If a position falls behind the 64 KiB suffix, the result stays out-of-sync, returns no bytes, and leaves next at the requested position. Moving to a newer position cannot reconstruct a screen.

Recover with snapshot: it returns the owner's complete current display, cursor coordinates (zero-based), cursor visibility, alternate-screen flag, geometry and matching byte position. Only a successful snapshot is snapshot-current. Render it as a complete display and poll snapshots for subsequent current views; it is not serialized parser state, so do not feed later byte reads into it as if it were an emulator checkpoint. Byte observations remain labelled stream-only. A conservative 256 KiB cell-content budget is checked before rendering, and snapshots are capped at 256 KiB encoded JSON; an oversized view returns out-of-sync with recoveryError and no screen. Keep the viewer out of sync until a later snapshot succeeds. Closed shells expose their final available view; loss labels any retained view last-known-screen, never live. Explicit removal makes further requests fail rather than inventing a replacement.

The existing pinned Charm VT interprets the screen with at most 1,000 scrollback lines, separately from bounded byte history. Its parser limit is 4 MiB; geometry, parser and response bounds are not a total-memory or universal-terminal-compatibility guarantee. Resize clips existing contents instead of reflowing them. Snapshots are render-only: they do not inject terminal-query replies; the controller can answer queries through the input route. Remote clipboard/title controls do not reach the observer's terminal. Shell bytes are not collected or logged. The workspace follower exposes lifecycle, controller changes, input byte counts and provider results without terminal contents. Successful controls return requestID for correlation and optional auditError if persistence failed after execution; preserve the returned token and inspect before continuing.

Public Hovel session-command route

The CLI uses the existing owner-protected workspace socket and supported RunSessionCommand. Select a burrow-shell-v1 ID from ListSessions. The request is {"SessionID":"ID","Request":{"command":"input","inputEncoding":"utf-8","inputData":"JSON_OBJECT"}}, where the nested JSON contains the token and base64 data. Claim, takeover, resize and release use the same private-input fields and their documented schemas. Observe uses args:["OFFSET"]; snapshot optionally accepts args:["HISTORY"] (0–1000 lines back), and inspect has no arguments. No token-bearing positional arguments, input paths, config or reconnect fields are accepted. The public result's stdout contains the same JSON object returned by Burrow. These controls arbitrate input; they do not create a security boundary against the workspace's operating-system owner or substitute for confirmed connection creation.

Open, observe, control and detach

shell NAME creates and controls a retained shell on the selected existing connection. shell NAME SESSION_ID observes that exact retained session without taking control. Opening a workspace discovers its recognized shells as observer tabs; shells refreshes discovery. A failed inventory remains UNVERIFIED and preserves previous tabs. No fresh authentication or reconnect happens during attachment.

shell gateway
# Ctrl+] releases this attachment's control and returns to management
shells
resume 1
# Observe first; Alt+T explicitly takes control
shell-control 1
shell-detach 1
# Copy the opaque ID from the pane or session list to another frontend:
shell gateway SESSION_ID
# Close exactly the selected retained shell:
shell-close 1

The pane shows CONTROL or OBSERVE, controller label, remote dimensions, synchronization and the opaque session ID. Controller labels are descriptive, not proof of liveness. Alt+T or shell-control [ID] performs a generation-checked takeover and applies the pane size. Old controller input, resize and release are fenced immediately by the owner. A competing takeover or uncertain write is shown as an error; inspect the shell before explicitly taking control again. Input is bounded and refused when busy, with no automatic replay of uncertain bytes.

Only CONTROL sends ordinary keys, Ctrl+C, Ctrl+D and supported mouse input to the remote terminal. OBSERVE never writes or resizes. Local observer resize clips the view while preserving the controller's remote geometry. Resuming or switching an existing tab does not claim control; new-shell creation does. Remote OSC clipboard/title requests stay inside the owner emulator. Input encoding uses the owner's supported input modes; remote control bytes are never replayed to the operator terminal.

Ctrl+] or Alt+B detaches to management, releasing only this attachment’s claim. shell-detach [ID] does the same from management. Tabs continue observing independently, and the remote shell, working directory, programs and dimensions remain. Switching between tabs or workspaces backgrounds a shell without releasing its claim. resume ID selects a tab; Alt+T is needed after release or takeover. An abruptly disappeared frontend leaves a descriptive claim until explicit takeover; there is no automatic expiry.

shell-close [ID] explicitly ends one retained shell for all attachments. The connection, sibling shells, forwarding and transfers remain. With no ID, close/control/detach select the last selected shell. TUI numbers are workspace-local positions and renumber when tabs close. The opaque Hovel ID identifies the retained shell across frontends; do not confuse it with the TUI number. exit ends the selected remote shell without closing its connection. A background exit does not steal another active view.

Navigate shells

The left sidebar has workspaces above a midpoint New/Menu row and SHELLS - SSH below. Workspace selection returns to management. The lower tree stays expanded, one child per shell; wheel or F6, arrows and Enter reach overflow independently of the upper workspace list. Each shell has a clickable top tab. Alt+1–9 selects a numbered shell; Alt+Left/Right cycles. Narrow strips keep the selected tab visible. Burrow controls retain Catppuccin semantic colors, NO_COLOR labels and keyboard access.

If text is selected, Ctrl+C copies it; Escape clears selection before Ctrl+C can interrupt the remote program. Shell screens are not durable evidence. Use retained runs for structured command completion, exit status and collected output.

History, geometry and recovery

Each shell has independent screen, cursor, alternate buffer, supported input modes and at most 1,000 history lines in owner memory. Shift+PgUp/PgDn scroll; Shift+Home/End choose oldest/live output. Wheel scrolls when the remote program has not requested mouse input. History navigation is local to the observer and works without a controller claim. Historical views are labeled snapshot-history with a hidden cursor. session snapshot CONNECTION ID HISTORY exposes the same bounded history without input or resize. Closing the shell discards its history.

The active controller's pane geometry follows local resize, including while backgrounded. Observers preserve it. Invalid geometry is visibly refused while retaining the last accepted size; new-shell creation requires valid dimensions. Dimensions are 1–1000 per axis with at most 20,000 cells. The pinned VT clips rather than reflows old output on resize.

Views poll complete owner snapshots, independent of rendering and input. A missed-byte gap is recovered from the current snapshot and remains identified in the pane. Snapshot failure keeps the last display visibly out of sync; it never treats an incomplete history suffix as a current screen. LOST and UNVERIFIED remain distinct from empty inventory and successful close. Remote outcomes can be uncertain. There is no automatic reconnect, owner adoption or shell reconstruction after daemon/module loss.

Quit reviews connections and shell counts across all opened workspaces. Keep running releases this frontend's claims, retains shells and exits; Close connections verifies and tears down exactly the reviewed resources before exit; Escape cancels without changing resources. Saved settings, collected evidence and Hovel remain. Local editors and the embedded Hovel CLI end with the frontend. Normal exit and handled termination restore termios, cursor and alternate screen; SIGKILL cannot execute terminal cleanup.

Ownership, older managers and terminal compatibility

All shells on a named connection reuse its established master socket and authentication, including its selected route. The retained owner verifies the connection, socket identity and peer PID before starting each multiplexed SSH client with a controlling PTY. ProxyCommand=/usr/bin/false refuses fresh-login fallback after master loss. The connection-owned SOCKS proxy remains independent.

Control, input, resize, independent observation and snapshots use public Hovel session commands through the single base burrow module. Tokens travel in private request bodies, never argv, logs or evidence. Terminal bytes remain bounded owner memory. Burrow reuses the pinned Charm VT and Bubble Tea host; no new dependency or terminal service is required.

Older managers without this snapshot/input-mode contract are refused. Explicitly review burrow --workspace /absolute/path workspace restart, then confirm the returned digest. This closes that manager's connections and shells; reconnect explicitly afterward. Saved settings, collected evidence and Hovel remain. Cleaning build outputs cannot replace a retained owner.

This preserves LazySSH's native terminal flow and terminal checks: verify a live connection, request a TTY and return to management after exit. Intentional differences are retained shared lifetime, explicit control, embedded VT/history and refused fallback authentication. Custom shell selection, Terminator, automatic terminal launch, graphics, enhanced keyboard protocols and universal application compatibility are not claimed.
