Interactive SSH shells

After connecting, enter shell NAME in management, or run burrow --workspace /absolute/workspace shell NAME from a terminal. The CLI opens the same management frame with the SSH pane selected. The shell uses the server account's normal login shell through the existing authenticated master; it never connects or authenticates again.

Controls and lifetime

Ordinary keyboard input, including Ctrl+C and Ctrl+D, reaches the remote terminal. exit ends the shell and returns to management while preserving the connection. Ctrl+] or Alt+B returns to management while keeping the shell alive; choose the workspace's Shells control to return to its pane, or enter shell-close to explicitly close that local client. Opening another shell reuses the master. If text is selected, Ctrl+C copies it; Escape clears selection before Ctrl+C can interrupt the remote program. This first slice permits one local SSH shell per workspace; multiple-shell selection and full background/resume workflows belong to issue #49.

The Shells sidebar reports the frontend's local opening/running/closing state. The pane identifies its connection and labels output as local and not recorded. Initial and subsequent geometry follow the center pane, including when it is hidden. Invalid outer geometry is refused visibly while retaining the previous size; new shell launches wait for valid geometry. Shift+PgUp/PgDn scroll history and Shift+Home/End select oldest/live output. SSH history retains at most 1,000 lines in memory, with continuous output draining. Closing the shell discards that history. No terminal transcript or collected artifact is created.

Quit reviews connections across opened workspaces. Keep running preserves daemon-owned connections; Close connections tears down the reviewed connections; Escape cancels. Actual frontend exit ends and reaps all its local terminal clients. Connection-wide close or master loss also ends attached shells. Ending the local SSH client does not prove termination of deliberately detached remote processes. Saved settings and existing artifacts remain intact.

Ownership and compatibility

The shared production command verifies the retained burrow manager, generation, connection creation, runtime reservation and live master. Its public Hovel session command shell GENERATION CREATION returns verified connection metadata only. The frontend checks the socket inode and peer PID before launching an ordinary OpenSSH multiplexed client with a controlling PTY. ProxyCommand=/usr/bin/false prevents a fresh-login fallback if the master disappears. Earlier owners without this command are refused and must be explicitly closed and recreated with the current build.

PTY bytes and resizing remain frontend-local. They do not use Hovel's session I/O or a Hovel resize API, and are not Hovel-recorded evidence. The same base public module and existing confirmation/logging contracts remain in use. Local shells use the existing pinned Charm VT and Bubble Tea terminal host; no dependency or terminal service was added. Remote OSC clipboard/title requests stay inside the emulator. Burrow's controls retain the Catppuccin theme and no-color/narrow layouts.

This follows LazySSH's native terminal flow and terminal checks: verify a live connection, request a TTY, wait for exit and return to management. Intentional differences are the embedded VT, explicit on-demand launch, local history, and refusal of fallback authentication. Custom shell selection, Terminator and automatic terminal launch on connect are not part of this slice. The pinned VT clips rather than reflows old output on resize; graphics, enhanced keyboard protocols and universal terminal-application compatibility are not claimed.
