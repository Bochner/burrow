Release preparation

A version change on main publishes the exact archive and wheel tested by Repository CI. Release promotion does not rebuild them.

Prepare the version

  1. Increment root VERSION above main once per PR: patch for fixes/tooling, minor for compatible features, major for breaking changes.
  2. Add a matching nonempty CHANGELOG section describing user-visible changes and verification.
  3. Recheck the version after updating from main. Push, PR and merge still require owner authorization.

Stable versions use X.Y.Z; development versions use X.Y.Z.devN and publish as prereleases. Unchanged versions skip publication. Downgrades, missing notes and existing tags pointing elsewhere fail; tags are never moved.

Smoke checks cover archive extraction, offline pipx installation/upgrade/uninstall, CLI behavior, embedded skills and pinned Hovel startup. Installing a new frontend never automatically replaces live workspace owners.

Automatic GitHub publication

Release validates main membership, source run/attempt, artifact digest, exact files and checksums. It tags the immutable tested revision and uses its changelog notes. Rerunning can complete the same release without replacing existing assets.

Manual rehearsal and recovery

DestinationEffect
rehearsalValidate a successful main bundle without publishing.
githubComplete GitHub publication for an existing matching version tag.
github-and-pypiAlso publish the verified wheel through the separately configured manual PyPI path.

Dispatch from main. Supplied tags must match VERSION and the checked-out revision. A tag push alone does not publish. PyPI publication remains an explicit manual choice.

Bundles expire after 30 days. If main HEAD has no verified bundle, dispatch Repository with force_full, then retry Release. Reconstruction of older revisions is unsupported; prepare a new release instead of substituting another revision's files.

GitHub and PyPI publication can finish independently. Inspect both results before retrying; a conflicting same-version digest fails. One-time publisher account setup is tracked separately from this public release procedure.
