Hovel integration

Burrow uses Hovel’s public SDK and protocol through the single burrow@0.1.0 module for workspace inspection, saved profiles, retained SSH connections, forwarding, files, runs, reports and chains. See connection operation and legacy-module transition.

Boundary requirements

Hovel module stdout belongs exclusively to framed JSON-RPC. The separate Charm frontend owns terminal rendering and local interactive shells; retained modules own SSH connections and runs. Hovel owns workspaces, sessions, confirmations and collected artifacts.

Saved-chain automation uses explicit workspace selection and Hovel's confirmation and launch policy. Connection and tunnel chains either create an explicitly confirmed connection to a running SSH server or consume an exactly selected live tunnel. Tunnel consumption is bounded owner-mediated HTTP, with no transparent arbitrary-module routing or generic Mesh bridge. Markdown reports remain ordinary Hovel artifacts usable outside Burrow.

Evidence and decisions

Read the Hovel integration research and the decision map. Research recommendations are not approved architecture, and the linked initial research predates the production SDK and controlled SSH acceptance. Historical prototype identities are not production modules.
