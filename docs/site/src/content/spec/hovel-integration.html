Hovel integration

Burrow uses Hovel's public SDK and daemon protocol through one base module, burrow@0.1.0. Hovel runs locally; the SSH target needs no Burrow or Hovel installation.

Who owns what?

OwnerResourcesFrontend exit
Burrow frontendRendering, shell attachments, editors and embedded Hovel CLI.Frontend processes end; shell claims are released on normal detach.
Hovel-retained Burrow moduleSSH masters, listeners, transfers, shared shells and separate run sessions.Keep running retains them. Explicit close or manager loss ends dependent resources.
Hovel daemonWorkspace state, session records, plans, confirmations and collected artifacts.The daemon remains running.

Module stdout is exclusively framed JSON-RPC. SDK logging carries progress; the separate frontend renders the terminal.

Integration surfaces

  • CLI reference: commands, JSON results and installed capability discovery.
  • Saved Hovel chains: confirmed connection creation or requests through exactly selected tunnels.
  • Local automation: retained local tools and documented public daemon operations.
  • Shared sessions: one controller, independent observers and explicit takeover.

Burrow publishes no separate REST service or SDK. MCP is optional for external agents. Tunnel consumption is bounded owner-mediated HTTP, not transparent routing for arbitrary modules.

Decisions and evidence

The decision map records accepted scope. Initial integration research and historical prototypes are evidence, not current implementation specifications. See resource lifetimes for loss and recovery limits.
