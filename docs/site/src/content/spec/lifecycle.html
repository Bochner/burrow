Quit, detach and close

Leaving a view, ending a shell and closing its connection have different effects. Choose the smallest resource scope you intend to end.

ActionEndsRemains
Ctrl+] or shell detachThis attachment's control.Shell, working directory, programs and other attachments.
Remote exit or selected shell closeOne shell.Master, sibling shells, tunnels and transfers.
Close output/file viewObservation only.Run, capture or transfer and other viewers.
Quit → Keep runningFrontend processes and its shell claims.Daemon-owned SSH resources, retained runs and collected evidence.
close NAMEOne connection's master, shells, transfers and listeners. Remote runs lose access.Sibling connections, settings, collected evidence and daemon.
Quit → Close connectionsReviewed connections across workspaces opened in this frontend.Settings, collected evidence and daemons.
Quit → Cancel / EscapeNothing.Frontend and resources.

Leave and return

  1. Inspect connections, transfers and runs. Collect important completed output.
  2. Enter quit and review all opened workspaces. Choose Keep running or Close connections.
  3. Reopen the same workspace. Select a retained shell to observe it; Alt+T explicitly takes control.

Failed or uncertain cleanup keeps Burrow open. A disappeared frontend can leave a shell claim until explicit takeover; a label never proves its controller is alive.

Close a connection from the CLI

burrow --workspace /absolute/workspace inspect gateway
burrow --workspace /absolute/workspace close gateway
# After approving the exact returned review:
burrow --workspace /absolute/workspace close gateway --yes --review HASH

A changed creation or resource state requires another review. --yes alone explicitly approves the current selection. Names and ports can be reused; they are not permanent identities.

Manager retirement and loss

Workspace restart or retire ends the whole connection manager, including concurrent additions. Separate run records remain, but their remote access ends with the master. Restart registers the current executable; neither action reconnects SSH.

After daemon or module loss, live state may be lost or unverified. Saved profiles and collected artifacts remain; uncollected output and remote cleanup can be unknown. There is no automatic shell reconstruction, socket adoption or fresh login. Follow ownership recovery.
