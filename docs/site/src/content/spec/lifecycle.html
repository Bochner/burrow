Quit, detach and close

A connection is an authenticated SSH transport. A shell is one terminal using it. Leaving a view, ending a shell and closing its connection have different effects.

The TUI's interactive shells are frontend-local. A second Burrow process cannot resume them, and Keep running does not retain those local shells after frontend exit. Current-source session lifecycle commands create separate retained shells that do survive launcher exit and Keep running. Shared controller/observer access and TUI migration remain follow-on work under the accepted shared-session decision.

Leave and return

  1. Use connections, transfers and run list to inspect work in the selected workspace. Collect important completed run output before leaving.
  2. Enter quit in management. Review the connections across all workspaces you opened. Keep running retains the daemon-owned resources; Close connections ends the reviewed connections.
  3. Reopen Burrow with the same absolute workspace path. Inspect the retained resources. Open a new shell if needed; the old frontend's shells have ended.

Failed or uncertain teardown keeps Burrow open with an error. Inspect that result before retrying. Ending a local SSH client never proves that deliberately detached remote processes have stopped.

Close one connection from the CLI

burrow --workspace /absolute/workspace inspect gateway
burrow --workspace /absolute/workspace close gateway
# Current source: copy the digest from the review after approving it.
burrow --workspace /absolute/workspace close gateway --yes --review HASH

Current source binds the review to the exact connection creation and observed state. Changed state requires another review. --yes without a digest explicitly approves the current selection; v0.1.0 supports that older form. Connection names can be reused later, so never treat a name or port as a permanent identity.

Manager retirement and loss

The current-source workspace restart and workspace retire commands review the entire connection owner, including connections added concurrently. They preserve the daemon and separate retained-run records, but ending their SSH masters loses access for remote runs. Restart also registers the current executable. Neither reconnects SSH or starts a replacement manager. See the headless lifecycle workflow.

After owner or daemon loss, saved profiles and already collected artifacts remain. Live state may be lost or unverified, uncollected output may be unavailable, and remote process cleanup may be unknown. There is no automatic login, shell recovery or adoption of stale sockets. Follow ownership recovery guidance.
