Workspace navigation

Headless workspace and manager operation

Choose one absolute canonical path with --workspace. Each CLI invocation selects its own workspace; it does not change another frontend's selection. Open initializes or reuses the verified workspace through the same operation as the TUI. Inspect only verifies an existing daemon and never creates a destination or replaces an unavailable owner. The older status spelling remains an initializing alias for open.

burrow --workspace /absolute/workspace workspace open
burrow --workspace /absolute/workspace workspace inspect
burrow workspace list /absolute/workspace /absolute/other-workspace

List observes only the supplied paths. Its result declares scope: explicit-paths and registryAvailable: false; each entry is verified or unverified with an error. This is not an authoritative inventory of all workspaces. Do not combine list with --workspace. Missing or repeated workspace selection refuses rather than choosing a target. Daemon health is separate from SSH state: use connections and inspect NAME for the shared connection owner's observations.

burrow --workspace /absolute/workspace workspace restart
# Read the review and copy its digest only after approving the whole owner:
burrow --workspace /absolute/workspace workspace restart --yes --review HASH
burrow --workspace /absolute/workspace workspace retire
burrow --workspace /absolute/workspace workspace retire --yes --review HASH

Restart and retire first return a JSON review with the exact daemon and manager identities and current connections. Confirmation binds the action and manager incarnation. The connections array is a pre-action observation, not an exhaustive cleanup inventory when concurrent additions occur. It covers the whole owner, including concurrent additions; close other frontends before confirming if they could add work. Both end that manager's connections and dependent shells, transfers and tunnels while preserving the Hovel daemon, saved settings, collected evidence and separate retained runs. Restart also registers the current executable for future operations. Neither command opens a TUI, starts a replacement manager or reconnects SSH. The next explicitly approved connection activates a manager. The legacy terminal restart [--yes] keeps its interactive behavior and opens a TUI.

Use the existing saved-setting and connection commands: profile select and profile load never connect. profile connect NAME [--as NAME] returns the same immutable connection review as connect; repeat with --yes --review HASH to bind approval. close NAME now returns a digest too: close NAME --yes --review HASH refuses a replacement creation or changed state instead of closing it. Other connections survive selected close. Use current-user key/agent authentication or the existing private interactive challenge flow; do not place passwords or passphrases in recorded agent command arguments. Lost connections still require explicit reconnect.

Workspace subcommands, close and profile connect emit JSON for pipes and use the shared semantic colors on human terminals: results and reviews on stdout, errors as {"error":{"operation":"workspace.retire","code":"review_changed","message":"…"}} on stderr with exit 1. Errors include the workspace and review when available. A missing or changed review retains resources; cleanup_unconfirmed can follow partial cleanup and requires inspection before retrying. registration_failed includes a retired review state because the owner has already ended. Close and profile connect use code operation_failed with a descriptive message for validation, ownership, stale review and execution failures; no automatic retry is implied. Global flag parsing and other command errors remain text. See the generated workspace routes and error contract.

An already open TUI automatically observes CLI-created and closed connections through the same retained owner. Failed observations show UNVERIFIED, never an empty inventory. Frontend-local shells and workspace activity following remain separate capabilities. aspect burrow workspace-check exercises production CLI and a separate PTY against the controlled SSH server, including stale confirmations, sibling and evidence preservation, loss, cleanup and unverified observation. The lifecycle partition includes this check; aspect test //core/cmd/burrow:workspace_test covers read-only selection and discovery without SSH.

Terminal navigation

The left sidebar is split at the midpoint New/Menu row: WORKSPACES above, SHELLS - SSH below. Clicking a workspace above returns to its Burrow management view. The lower tree stays expanded with every local shell beneath its workspace; each list scrolls independently when needed, without replacing shells with a summary. The Burrow tab retains saved, active SSH and tunnel sections, command output and completion. The Hovel tab hosts its interactive CLI; shell NAME opens another independent SSH pane through the existing master. Every shell has its own clickable top tab. Select a tree child, click its tab, or use resume ID to return to that exact shell.

The workspace list contains only explicit paths opened in this frontend session. The pinned public Hovel contract has no cross-workspace enumeration operation. Burrow neither scans directories nor persists another live-resource registry. New asks for a workspace name; Enter or Create & open creates and opens it under $XDG_DATA_HOME/burrow/workspaces/<name>, falling back to ~/.local/share/burrow/workspaces/<name> when XDG_DATA_HOME is unset or relative. Tab or a field click edits the optional parent Location; Ctrl+O or Browse paths selects a directory. The override applies to this creation only. The form shows the resulting destination, accepts absolute canonical locations or ~/…, and rejects invalid names and paths too long for even the shortest SSH connection name. Longer connection names must still fit the existing 90-byte socket-path limit. Opening the form does not create directories.

Creation uses the same verified launch operation as the CLI, preserving its offline/package options, permissions and refusal policy. An existing destination is opened only if it passes the same ownership checks; it is never overwritten or blindly adopted. These are ordinary Hovel workspaces: use the same exact workspace and daemon for Hovel chains consuming Burrow resources. The embedded Hovel CLI already does so. A common parent folder does not share resources across different workspaces. The standalone CLI continues to require an explicit --workspace.

Each workspace retains its command draft, completion, history, output and scroll position, selected connection and background terminals. Top workspace selection shows management; select a shell or Hovel tab to resume it. Selecting a known workspace only verifies it; it never launches replacement daemons, reconnects SSH or closes other resources. Asynchronous commands and timers carry their originating workspace and a single-use request identity. A delayed result updates its original workspace. Escape can dismiss a pending launch; its completion does not steal the selected workspace, and launch failures remain in the originating workspace output.

The center shrinks with terminal width, and both sidebars remain visible while narrowing as needed. Tables keep left-aligned section titles and centered headers and values with Catppuccin Mocha semantic colors. Long values truncate within their columns; selected connection details remain available through metadata. There is no blocking 160×40 resize screen. Extremely small terminals show a clipped application view and allow Ctrl+C to exit while suppressing hidden controls. Modal input captures pointer events and preserves the management draft.

The Hovel bubble is green only after a recent verified success, yellow while checking, unknown or older than eight seconds, and red after verification fails or refuses identity. The selected workspace is polled without overlapping checks, normally three seconds after an observation. Metadata shows last-success age, measured verification duration, last-known PID and endpoint. Verification includes local receipt/process checks: its duration is not SSH or network latency. Hovel daemon identity, the Burrow connection owner and SSH connection snapshots are separate states.

Sidebar circles describe observed SSH health, independently of selection: filled green means connected, half-filled yellow means opening/closing or reconnecting, and open red means disconnected or failed. Dotted circles distinguish unknown observations (muted) and unverified observations (red). Workspace health prioritizes failures and transitions over healthy connections.
