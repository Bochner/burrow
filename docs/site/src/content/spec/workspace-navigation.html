Workspace navigation

A workspace holds connection names, saved settings and evidence. Select the same canonical absolute path in every frontend that should share resources.

Open and inspect from the CLI

burrow --workspace /absolute/workspace workspace open
burrow --workspace /absolute/workspace workspace inspect
burrow workspace list /absolute/workspace /absolute/other-workspace
CommandBehavior
workspace openInitialize or reuse the verified workspace. status is an alias.
workspace inspectVerify an existing daemon. Creates no workspace or replacement owner.
workspace list PATH…Observe only supplied paths; do not combine with --workspace.

List reports scope: explicit-paths and registryAvailable: false. It is not a global inventory. Each CLI invocation selects its own workspace; it never changes another frontend's selection.

Update or retire a connection manager

  1. Inspect current connections and close frontends that could add work.
  2. Request restart or retirement and read the returned owner review.
  3. Confirm the chosen action with its returned digest. Changed manager identity refuses confirmation.
burrow --workspace /absolute/workspace connections
burrow --workspace /absolute/workspace workspace restart
# After approving the returned review:
burrow --workspace /absolute/workspace workspace restart --yes --review HASH

Use workspace retire instead to end the owner without registering the current executable. Both actions cover the whole owner, including concurrent additions; the review's connection list is a pre-action observation.

EffectRestart / retire
Connections and dependent shells, listeners and transfersEnd with the selected manager.
Separate retained-run recordsRemain, but remote runs lose access when their SSH masters end.
Hovel daemon, saved settings and collected evidenceRemain.
Replacement manager or SSH loginNeither action starts one. The next explicitly approved connection activates a manager.

The terminal restart command has a separate interactive flow and opens the TUI. See runtime upgrades.

Navigate the terminal

The left sidebar lists workspaces above New/Menu and shells below. Click a workspace for management, or a shell child/top tab to observe that shell. The workspace list contains only paths opened in this frontend session.

Create a workspace

Choose New, enter a name, then press Enter or Create & open. The default location is ${XDG_DATA_HOME:-$HOME/.local/share}/burrow/workspaces/NAME; unset or relative XDG paths use the home fallback.

Tab selects the optional parent Location. Ctrl+O opens its path browser. The form previews the destination and validates permissions, names and socket-path length before creating anything. Existing destinations must pass ownership checks.

Switch and observe health

Switching preserves each workspace's draft, output, history and background terminals. It verifies the destination without reconnecting SSH or replacing a daemon. Delayed commands update their originating workspace.

IndicatorMeaning
Daemon greenA recent successful verification.
Daemon yellowChecking, unknown, or last success older than eight seconds.
Daemon redVerification failed or identity was refused.
SSH circlesConnected, transitioning, disconnected, unknown or unverified; independent of row selection.

Metadata includes last-success age, verification duration, PID and endpoint. Verification duration is not network latency. Failed observation remains UNVERIFIED, not an empty inventory.

Results and recovery

Workspace commands emit results/reviews on stdout and JSON errors on stderr with exit 1. Missing or stale review confirmation preserves resources. cleanup_unconfirmed can follow partial cleanup; inspect before retrying. See the error contract.

An open TUI observes CLI-created connections through the same owner. Run shells to refresh retained shell tabs. Use follow for activity and ownership recovery after loss.
