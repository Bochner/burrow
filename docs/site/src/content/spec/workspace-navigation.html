Workspace navigation

The left sidebar is split at the midpoint New/Menu row: WORKSPACES above, SHELLS - SSH below. Clicking a workspace above returns to its Burrow management view. The lower tree stays expanded with every local shell beneath its workspace; each list scrolls independently when needed, without replacing shells with a summary. The Burrow tab retains saved, active SSH and tunnel sections, command output and completion. The Hovel tab hosts its interactive CLI; shell NAME opens another independent SSH pane through the existing master. Every shell has its own clickable top tab. Select a tree child, click its tab, or use resume ID to return to that exact shell.

The workspace list contains only explicit paths opened in this frontend session. The pinned public Hovel contract has no cross-workspace enumeration operation. Burrow neither scans directories nor persists another live-resource registry. New asks for a workspace name; Enter or Create & open creates and opens it under $XDG_DATA_HOME/burrow/workspaces/<name>, falling back to ~/.local/share/burrow/workspaces/<name> when XDG_DATA_HOME is unset or relative. Tab or a field click edits the optional parent Location; Ctrl+O or Browse paths selects a directory. The override applies to this creation only. The form shows the resulting destination, accepts absolute canonical locations or ~/…, and rejects invalid names and paths too long for even the shortest SSH connection name. Longer connection names must still fit the existing 90-byte socket-path limit. Opening the form does not create directories.

Creation uses the same verified launch operation as the CLI, preserving its offline/package options, permissions and refusal policy. An existing destination is opened only if it passes the same ownership checks; it is never overwritten or blindly adopted. These are ordinary Hovel workspaces: use the same exact workspace and daemon for Hovel chains consuming Burrow resources. The embedded Hovel CLI already does so. A common parent folder does not share resources across different workspaces. The standalone CLI continues to require an explicit --workspace.

Each workspace retains its command draft, completion, history, output and scroll position, selected connection and background terminals. Top workspace selection shows management; select a shell or Hovel tab to resume it. Selecting a known workspace only verifies it; it never launches replacement daemons, reconnects SSH or closes other resources. Asynchronous commands and timers carry their originating workspace and a single-use request identity. A delayed result updates its original workspace. Escape can dismiss a pending launch; its completion does not steal the selected workspace, and launch failures remain in the originating workspace output.

The center shrinks with terminal width, and both sidebars remain visible while narrowing as needed. Tables keep left-aligned section titles and centered headers and values with Catppuccin Mocha semantic colors. Long values truncate within their columns; selected connection details remain available through metadata. There is no blocking 160×40 resize screen. Extremely small terminals show a clipped application view and allow Ctrl+C to exit while suppressing hidden controls. Modal input captures pointer events and preserves the management draft.

The Hovel bubble is green only after a recent verified success, yellow while checking, unknown or older than eight seconds, and red after verification fails or refuses identity. The selected workspace is polled without overlapping checks, normally three seconds after an observation. Metadata shows last-success age, measured verification duration, last-known PID and endpoint. Verification includes local receipt/process checks: its duration is not SSH or network latency. Hovel daemon identity, the Burrow connection owner and SSH connection snapshots are separate states.

Sidebar circles describe observed SSH health, independently of selection: filled green means connected, half-filled yellow means opening/closing or reconnecting, and open red means disconnected or failed. Dotted circles distinguish unknown observations (muted) and unverified observations (red). Workspace health prioritizes failures and transitions over healthy connections.
