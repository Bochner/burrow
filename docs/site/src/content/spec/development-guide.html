Development guide

Aspect CLI is the entry point for builds, tests, formatting, packaging, and documentation. Run aspect help to discover the checked-in AXL tasks.

aspect burrow-check
aspect burrow-site build
aspect burrow-site check
aspect burrow-site stage

The full gate builds metadata and prototype packages, checks the generated documentation, and exercises SDK protocol, daemon reuse and SSH behavior in bounded fixtures. The SSH fixture requires exact host OpenSSH binaries; aspect burrow-check ci builds all prototypes and runs the portable tests without that fixture. Passing observations of known gaps do not establish production SSH parity. Staging writes the generated artifact to _site/.

docs/research/Source-backed evidence, distinct from decisions.

Runnable evidence lives in core/prototype_sdk/ and core/prototype_transport/ on main. When production implementation begins, place the Go application under core/ following Hovel's organization. Create modules/ only for actual module packages and sdk/ only if Burrow exposes its own supported SDK. Keep upstream checkouts under ignored .references/. Internal package layering and any nested workspace remain Wayfinder decisions.

Documentation authoring

Edit literal HTML fragments in docs/site/src/content/. Each begins with a burrow-doc JSON metadata comment and contains exactly one h1. Metadata generates the contents, chapter numbers, sidebar, and search. Change shared chrome in components/layouts; keep generated _site/ out of source control.

Publishing

CI validates and stages the site. The Pages workflow promotes the exact docs-site artifact from successful main-branch CI; manual dispatch runs the same checks. GitHub Pages must be enabled separately in repository settings. A private repository does not by itself make its Pages site private.

Upstream provenance

The book adapts Hovel's Apache-2.0 Astro renderer and styling. See the pinned source and adaptation notes.
