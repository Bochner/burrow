Development guide

Aspect is the entry point for builds, tests, formatting, packaging and documentation. Start with aspect help.

Choose a check

CommandScope
aspect burrow-check ciProduction package and portable checks; no Docker.
aspect burrow-check verify SUITEOne routine partition; deterministic tests cache, external/process/race/fuzz checks stay fresh.
aspect burrow-check preflightUncached release rehearsal: portable, nine SSH suites, Hovel compatibility and measured coverage.
aspect burrow ssh-checkNine SSH partitions against digest-pinned disposable Docker servers.
aspect burrow-site checkBuilt pages, internal links/assets, search and report UI checks.
aspect burrow-site stageMaterialize the declared site under _site/.

Full checks require Docker and OpenSSH client tools. Partitions are portable, lifecycle, files, reverse, shell, chains, reports, automation, follow, runs and hovel. Each target runs once; failed tests are not retried.

Keep application code under core, documentation under docs/site, tooling under docs/tools/docs and research under docs/research. Create modules/ or sdk/ only for actual supported packages. Upstream checkouts belong under ignored .references/.

Module boundary

All capabilities use the single base Burrow module. A second public identity requires an explicit owner requirement explaining why the base cannot satisfy it. Internal packages and retained subprocesses do not justify another identity.

The canonical manifest is core/connection/hovel-module.yaml. Use the public Hovel SDK/protocol; module stdout is framed JSON-RPC and progress uses SDK logging. Preserve confirmation, audit and ownership contracts.

Format and analyze

aspect burrow format-check
aspect burrow python-format-check
aspect burrow go-analysis
aspect burrow python-lint
aspect burrow race-check
aspect burrow fuzz-check

Use aspect burrow format or python-format to repair formatting. Declared package globs include new production files; dependencies and historical prototypes are excluded.

Fuzz failures retain minimized inputs under bazel-testlogs/core/connection/command_fuzz_test/test.outputs/. Check useful regressions into core/connection/testdata/fuzz/FuzzCommandLine/, then replay:

aspect test //core/connection:command_fuzz_test \
  --bazel-flag=--test_arg=-test.fuzz= \
  --bazel-flag=--test_arg=-test.run=FuzzCommandLine/HASH

Write documentation

Edit HTML fragments under docs/site/src/content/. Each starts with metadata and contains one h1:

<!-- burrow-doc: {"title":"Example","group":"Foundations","order":170} -->
<article>
  <h1>Example</h1>
  <p>Explain the outcome, then show the command.</p>
</article>
  • Lead with the task or outcome. Use short paragraphs, ordered workflows and comparison tables.
  • Put runnable examples in pre/code blocks with a data-lang surface label.
  • Use diagrams for ownership, traffic direction or lifecycles; provide accessible titles/descriptions and explanatory text.
  • Keep one-time account setup, historical acceptance and detailed test narratives outside the operator book.
  • API content comes from the production capability inventory; do not hand-maintain a second command catalog.
aspect burrow-site check
aspect burrow-site stage
# Optional rendered-page checks with an installed Chromium browser:
BURROW_DOCS_BROWSER=/absolute/path/to/chromium aspect burrow-site browser

The browser check exercises desktop/mobile scroll, diagram rendering and overflow. It uses an explicit local browser prerequisite; it is not a hermetic production acceptance suite. Keep generated _site/ out of source control.

Agent validation

aspect burrow agent-discovery
aspect burrow agent-exercise -- /absolute/new/evidence-directory

Discovery uses disposable configurations and Bubblewrap without network/model requests; absent clients are UNVERIFIED. The exercise publishes prompts for an external client and checks real resource behavior. An evaluator reviews its transcript separately. Neither is a default client/model prerequisite.

CI and PR preparation

  1. Work locally on the milestone/task branch; push, PR and merge each need owner authorization.
  2. Add a focused behavior check for nontrivial changes and run the relevant Aspect gate.
  3. Increment VERSION above main once per PR and add matching CHANGELOG notes. Recheck after updating main.
  4. Run Standards and Spec review against the branch baseline and originating requirements.

Application CI runs all eleven partitions plus coverage/report assembly. Safe same-repository evidence reuse requires matching source inputs; missing, expired or mismatched evidence selects full validation. Narrow prose-only PRs still run current documentation checks.

The required repository aggregate rejects failures, cancellations and unexpected skips. Main additionally smoke-tests the exact release bundle. Evidence/site/bundle retention is 30 days; extra failure diagnostics last seven days.

Hovel compatibility

The hovel partition requires the WAL-lock regression and both retained-manager proofs. Hovel v0.4.4 retires the old #86 exception; missing or failing results block the full gate.

Public test evidence

The Reports tab preserves Hovel's Overview, Linters, Coverage, Suites, Jobs and Targets. An initial build shows missing measurements. For a report with local evidence:

aspect burrow-check preflight
aspect burrow-site stage
aspect burrow-report render

Six production Go coverage targets measure executable lines, not branches. Capability reachability, JSON schemas and selected behavior are separate measurements. Passing checks do not imply exhaustive semantic equivalence or owner acceptance.

Keep evidence relevant to the source inspected. Local suites preserve previous inputs under .report-input/archive/. Diagnose archived failures; do not mix them into a candidate report. Full report rules live in the documentation contract.

Publishing

Successful main CI promotes its existing site artifact to Pages and its exact release bundle to GitHub. Pages skips deployment if main advanced; it does not rebuild. Version tags are never moved. See releasing.

Attribution

The theme adapts Hovel's Apache-2.0 renderer. Keep source pins and adaptation notes current.
