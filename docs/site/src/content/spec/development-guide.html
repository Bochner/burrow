Development guide

Aspect CLI is the entry point for builds, tests, formatting, packaging, and documentation. Run aspect help to discover the checked-in AXL tasks.

aspect burrow-check
aspect burrow-site build
aspect burrow-site check
aspect burrow-site stage

The full gate builds metadata and prototype packages, checks the generated documentation, and exercises SDK protocol, daemon reuse and SSH behavior in bounded fixtures. The production SSH fixture uses a digest-pinned disposable OpenSSH Docker container; Docker and local OpenSSH client tools are required. aspect burrow-check ci builds production packages and prototypes and runs portable checks without Docker. Run aspect burrow ssh-check for the controlled connection lab. The earlier transport proof retains its historical host-binary prerequisites and is runnable separately. Passing observations of known gaps do not establish production SSH parity. Staging writes the generated artifact to _site/.

Public module boundary

All production capabilities belong to the single base burrow Hovel module. A second public identity requires an explicit owner requirement in the originating issue explaining why the base module cannot satisfy it. Internal Go packages, retained sessions and subprocesses do not justify another public module. The canonical production manifest is core/connection/hovel-module.yaml, packaged with the frontend and embedded for registration. Review registration and SDK entry points against this rule. Historical core/prototype_* modules and the test-only legacy-identity fixture are bounded evidence, never additional production packages.

The setup/profile checks cover the fresh catalog and shared SDK routing. The controlled SSH gate checks real base-module connections and profile writes, legacy-owner retention/collision refusal/explicit close, manual catalog transition and sibling/evidence preservation. PTY checks preserve Hovel’s review/confirmation flow with the consolidated module’s danger allowance.

The Go application lives under core/ following Hovel's organization; aspect burrow package builds it and aspect burrow check runs its focused checks. Historical proofs remain under core/prototype_*/. Create modules/ only for actual module packages and sdk/ only if Burrow exposes its own supported SDK. Keep upstream checkouts under ignored .references/.

Documentation authoring

Edit literal HTML fragments in docs/site/src/content/. Each begins with a burrow-doc JSON metadata comment and contains exactly one h1. Metadata generates the contents, chapter numbers, sidebar, and search. Change shared chrome in components/layouts; keep generated _site/ out of source control.

Publishing

CI validates and stages the site. The Pages workflow promotes the exact docs-site artifact from successful main-branch CI; manual dispatch runs the same checks. GitHub Pages must be enabled separately in repository settings. A private repository does not by itself make its Pages site private.

Upstream provenance

The book adapts Hovel's Apache-2.0 Astro renderer and styling. See the pinned source and adaptation notes.
