File browsing and workspace roots

Use scp gateway in Burrow management to browse an existing live connection. Bare scp offers live workspace connections through the command picker. File mode uses structured SFTP over that connection's OpenSSH master; it never starts authentication. Missing, lost, replaced or unverifiable owners are refused. back or idle Ctrl+C returns to management without closing the connection, restoring its prompt, history and output.

Remote navigation

Each connection gets a file-mode tab beside Burrow, Hovel and the shell tabs, plus a matching entry in the left sidebar. Switching tabs preserves its directories, draft, listing and history without refreshing the remote directory. Entering file mode again selects the existing tab for that exact transport; a reconnected transport gets a new view. back closes only the selected file tab. Alt+B returns to management while retaining the tab; F6 focuses the tab bar for keyboard navigation.

ls
ls /var/log
cd /var/log
cd 'directory with spaces'
cd ~
pwd
tree /var/log
history
back

Listings include hidden entries and omit only . and ... They show permissions, owner, group, size in bytes, modification time, and name, oldest modification first with a name tie-break. Symlinks show their targets; explicit cd can follow directory links. Recursive trees never traverse directory links and label inaccessible subtrees or interrupted work as incomplete. Hard-link counts are intentionally omitted.

SFTP provides numeric ownership. A bounded, cached lookup of only the required account IDs supplies names when shell access and getent/cut are available. Otherwise a reduced-metadata notice accompanies numeric IDs; browsing remains available, including on SFTP-only servers. No uploaded helper is required. Remote control characters are escaped for display; use JSON CLI arguments for filenames that cannot round-trip through a terminal line editor.

File colors follow eza's distinction between file kinds and individual permission bits, using Burrow's Catppuccin palette: directories blue, executables green, links teal, and broken or refused entries red. Read permissions are yellow, write red, execute green, special bits mauve, and absent bits muted. Listings and trees use the same classification from observed metadata; coloring never triggers remote commands. All permission characters, directory suffixes and link targets remain visible without color.

Row actions and saved-connection editing

Right-click an active SSH row and choose Enter file mode. Right-click a saved connection to Execute connection through the usual connection recap or Edit in Vim. Keyboard users can focus a row with F6 and use Shift+F10. Escape or clicking outside dismisses the menu without executing an action.

Editing uses locally installed Vim in a Burrow terminal tab. Burrow supplies a small private configuration with Catppuccin syntax highlighting, line numbers, indentation and visible JSON syntax; personal vimrc files and plugins are not loaded or modified. Vim must include syntax support and its standard JSON runtime files. No editor is downloaded automatically.

Only the selected saved connection is staged, not the shared collection. Use :wq to save and exit, or :q! to discard unsaved changes. Burrow validates the saved JSON and applies it through the existing revision-checked profile command; edits never reconnect or alter active SSH resources. Keep the profile name unchanged. Invalid edits or concurrent collection changes are refused and the draft path is shown for recovery. Successful or unchanged edits remove their temporary staging directory. Quitting Burrow ends frontend-local editors; saved staging files from an unfinished edit remain in the editor's private temporary directory, while text not written by Vim is lost.

Workspace roots

Each workspace has private default directories WORKSPACE/burrow-files/uploads and WORKSPACE/burrow-files/downloads. Overrides persist in WORKSPACE/burrow-files/config.json. Opening a workspace creates absent defaults but refuses invalid, missing configured, inaccessible or symlink roots without falling back. A root must be an absolute canonical directory path owned by the current user with private permissions.

local
local download /absolute/download-root
local upload /absolute/upload-root
lcd upload 'sub directory'
lls upload
lcd download 'collected files'
lls
local /absolute/download-root

local shows effective roots. A root change persists but never moves or deletes old files. local PATH is the download shorthand. lcd changes only the frontend's current directory inside the selected root; lls lists it. Both default to download. Local links may resolve to relative or absolute targets inside that root. Broken and escaping links remain visible but cannot be traversed. Upload navigation never uses the process working directory as an implicit alternative.

Completion and server load

Tab and Shift+Tab cycle contextual, quoted path suggestions. Automatic discovery is asynchronous, debounced, cached for 30 seconds and limited to one in-flight lookup and at most one cache-miss start per second per connection. There is no idle directory polling, recursive prefetch or find discovery. Explicit listings are fresh and also populate completion. Account-name observations, including unavailable names, are cached for five minutes. Completion is an observation, not a guarantee that a path still exists.

Ctrl+C cancels current work; the prompt and help remain usable during slow discovery. Trees have a 30-second and 3,000-returned-entry ceiling, with partial results labelled. A large directory is read using the pinned SFTP client's directory-list API; the entry ceiling is not a guarantee of exactly 3,000 remote protocol records or bounded remote directory size. Responses are bounded to 768 KiB: trees may return fewer entries with an explicit incomplete notice; oversized flat listings are refused, asking for a narrower directory. No truncated listing is reported as complete.

CLI and Hovel

burrow --workspace /absolute/workspace scp gateway ls /var/log
burrow --workspace /absolute/workspace scp gateway tree /var/log
burrow --workspace /absolute/workspace local
burrow --workspace /absolute/workspace lls upload 'sub directory'
burrow --workspace /absolute/workspace files-history

The CLI returns structured JSON with full fields, independent of terminal width. CLI navigation is stateless: pass the path on each invocation. The TUI keeps current remote, upload and download directories independently. Canonical successful file commands use Hovel's retained burrow/files log chain, separate from profile history. Authentication answers, rejected input and speculative completion are not written as file history; paths and filenames deliberately supplied to successful commands are retained. History follows Hovel's retention, not a separate Burrow database.

The single burrow@0.1.0 module accepts the same file commands through its command configuration. Hovel's throw CLI exposes the JSON result in its result summary. Existing retained-manager consumers can use files GENERATION CONNECTION_CREATION QUERY_JSON; query fields are operation, path and an optional request id. Read-only control failures return a JSON error field in payload stdout, preserving diagnostics that the upstream payload-error response masks; consumers must check that field. Burrow's CLI converts it to a failed command. A cancel operation targets that exact ID. Reuse the owning session/generation/creation and refuse stale identity; name reuse never grants an old file view access to a new connection. Older running managers must be explicitly closed and restarted to gain newly built controls.

Reviewed downloads

get REMOTE [LOCAL]
mget PATTERN [LOCAL_DIR]
downloads
download-cancel ID

Both download commands follow the same flow: discover files, review a compact colored filename/size table with file count and total size, confirm, then observe copying and final outcomes. The recap omits repeated source/destination directories; renamed files and overwrites remain explicit. get defaults to the remote basename in the current download directory. mget matches regular files nonrecursively, including hidden files, and copies the reviewed list sequentially. It does not follow directory links or invoke a shell for matching. A single get follows a file symlink to its reviewed canonical target. Zero matches and failed discovery are distinct; neither writes files.

The review freezes the exact connection creation, root identity, sources, destinations and observed metadata. Existing files are marked OVERWRITE. Approval permits replacement only after successful copying and validation; new files use atomic publication that refuses an intervening destination. Access uses rooted directory handles and refuses outside paths and escaping symlinks. Changed roots, directories, destinations or source metadata require another review or produce an explicit per-file failure. New batch matches never expand an already approved list. Reviews stop at 1,000 files or 256 KiB and refuse oversized results rather than showing a partial list.

Transfers belong to the retained connection owner. They continue through tab changes, browsing, help, shell attachment and keep-running quit. back, Escape and leaving the view do not cancel copying. Use download-cancel ID for an acknowledged cancellation; connection close also cancels active transfers and waits for cleanup. Successful files remain available. Failure or cancellation retains a private .burrow-partial-ID-N file if copying began, while the original destination survives interrupted replacement. A publication or durability error states any uncertainty explicitly.

Progress appears in a scrollable popup the same size as Help, leaving the underlying file view in place. Press Escape to dismiss it without cancelling transfers; downloads reopens it from file mode or management. Bubbles progress bars show measured bytes for the current file and overall download; Bubbles timers refresh observations even while the popup is closed. Elapsed time is monotonic in the owner, independent of the view. Speed is labelled as an interval average and an overall average; ETA uses the overall average and remains unknown for unknown totals, insufficient measurements or a stalled interval. Receiving all bytes does not imply successful publication. Partial batches remain PARTIAL, with per-file complete, failed and cancelled outcomes.

downloads retrieves outcomes after leaving the view; the sidebar counts completed downloads and their bytes across the workspace, once per completed transfer file. File views show only their exact connection creation. Hovel's retained burrow/downloads logs hold starts and per-file/final outcomes. A lost owner with no final outcome is reported as interrupted, with the last retained measurements, not as a successful transfer. History follows Hovel retention. Working downloads are separate from registered Hovel evidence.

Retry selected failures by issuing get SOURCE DESTINATION for each chosen failed file shown in its outcome. Each retry gets a fresh review and restarts copying from zero; completed siblings are not recopied. Existing labelled partials remain available for inspection. Uploads remain separate work in #55.

burrow --workspace /absolute/workspace scp gateway get /var/log/example.log
burrow --workspace /absolute/workspace scp gateway get /var/log/example.log --review DIGEST --yes
burrow --workspace /absolute/workspace scp gateway mget '/var/log/*.log' logs
burrow --workspace /absolute/workspace downloads
burrow --workspace /absolute/workspace downloads ID
burrow --workspace /absolute/workspace download-cancel ID

CLI review returns structured JSON with files and a digest; repeat the unchanged command with --review DIGEST --yes. CLI paths are stateless and relative local destinations resolve inside the configured download root. The TUI resolves them against its download cwd and submits the frozen plan. Both use the single base Burrow module and confirmed Hovel throw path. Retained-owner controls separate read-only download-review/downloads from confirmed-adapter download submission and download-cancel; browsing's 30-second lifetime does not limit copying.

The local checks exercise roots, containment, cross-workspace isolation, persistence and the public Hovel module. The disposable real-SSH check covers remote metadata, navigation, links, restricted servers, interactive completion and cancellation, and server-side request counts. Presentation checks cover semantic colors, escaped text, help, restoration and narrow/no-color layouts. These are behavior checks, not a promise of subjective visual acceptance.

The workflow traces the pinned LazySSH SCP mode and its tests. Intentional differences include structured SFTP instead of parsing human command output, explicit root containment, bounded discovery, truthful partial results and ownership fallback, omission of hard-link counts and dot rows, and the shared Catppuccin/Charm presentation.
