File browsing and workspace roots

Browse and transfer files through an existing connection's SFTP subsystem. File mode never starts authentication or replaces a lost connection.

Browse a connection

scp gateway
ls /var/log
cd /var/log
pwd
tree .
history
back

Each connection creation has a file tab with its own directories, draft and history. Alt+B backgrounds it; back closes the view and restores management without closing SSH.

Listings show permissions, owner, group, bytes, modification time and name, including hidden entries. Symlinks show their targets; recursive trees never follow directory links. Inaccessible subtrees and cancelled work remain explicitly incomplete.

Numeric SFTP ownership is enriched with a bounded cached account lookup when shell tools are available. SFTP-only servers remain usable with a reduced-metadata notice. Remote control characters are escaped for display.

Roots must be canonical, private, current-user-owned directories. Changes persist in burrow-files/config.json but move no existing files. Missing configured roots are refused without fallback.

lcd changes only this frontend's directory within the chosen root; lls lists it. Both default to download. Links can be traversed only when they resolve inside the root. The process working directory is never an upload fallback.

Download and upload

  1. Enter file mode and choose the remote directory.
  2. Use local to check roots; place upload files inside the upload root.
  3. Submit get, mget or put. Review the exact file list, total size, destinations and overwrites.
  4. Confirm, then use transfers to inspect final per-file outcomes.
get example.log
mget '*.log' logs
put 'release artifact.tar' /srv/releases/artifact.tar
transfers
transfer-cancel ID
CommandBehavior
get REMOTE [LOCAL]One file; follows a file link to its reviewed canonical target. Default local name is the remote basename.
mget PATTERN [LOCAL_DIR]Nonrecursive regular-file matching, including hidden files; no directory-link traversal or shell matching. Up to four files copy concurrently.
put LOCAL [REMOTE]One regular file from the upload root. Default destination is its basename in the remote directory.

The plan binds connection creation, roots, files and observed metadata. Changed sources or destinations require another review or produce a per-file failure. New matches never expand an approved batch. Reviews refuse more than 1,000 files or 256 KiB.

New destinations use atomic publication that refuses intervening files. Approved replacements preserve the original until copying and validation succeed. Failure can retain a private .burrow-partial-ID-N file; durability uncertainty is reported.

Progress and cancellation

Progress shows per-file and overall bytes, percent, average speed, elapsed time and ETA, or Unknown when unmeasurable. Dismissing the popup, switching tabs or keep-running quit does not cancel copying.

transfer-cancel ID requests cancellation; inspect the final result. Connection close also cancels active transfers and waits for cleanup. Retry selected failed files with a fresh review; copying restarts from zero. downloads and download-cancel are download-specific aliases.

Retained outcomes survive leaving the view. Owner loss without a final result is interrupted, not successful. Transfer files and history are not automatically registered Hovel artifacts.

Use the CLI

burrow --workspace /absolute/workspace scp gateway ls /var/log
burrow --workspace /absolute/workspace scp gateway get /var/log/example.log
# After approving the returned digest:
burrow --workspace /absolute/workspace scp gateway get /var/log/example.log --review DIGEST --yes
burrow --workspace /absolute/workspace transfers ID

CLI navigation is stateless; supply paths each time. Download destinations resolve within the configured download root and upload sources within the upload root. The TUI instead uses its current directories within those roots.

For headless discovery cancellation, add --request scan-1 to a tree/list operation. Another process can submit scp gateway cancel scan-1. The acknowledgement is a request, not a final result; inspect the original operation. IDs are remembered for one minute and affect no transfers.

Row actions and profile editing

Right-click an active connection or focus it and press Shift+F10, then choose Enter file mode. Saved rows offer Execute connection and Edit in Vim; neither action skips validation or review.

Vim edits a private draft of the selected profile. :wq saves and exits; :q! discards unwritten edits. Keep its name unchanged. Invalid or conflicting edits preserve the draft path for recovery and leave live SSH resources alone. Personal Vim configuration and plugins are not loaded.

Discovery bounds

Completion is asynchronous, cached for 30 seconds, and limited to one lookup in flight and one cache-miss start per second per connection. Explicit listings are fresh. There is no idle directory polling.

Trees stop after 30 seconds or 3,000 returned entries. Responses are bounded to 768 KiB; oversized flat listings are refused. These limits do not bound a remote server's directory size. Incomplete results are labelled; Ctrl+C cancels active discovery.

See the file API and transfer API for schemas and result fields.
