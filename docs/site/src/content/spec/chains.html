SSH and tunnel chains

A saved Hovel chain can create a named connection or request HTTP through an existing tunnel. Both use the base Burrow module and normal Hovel planning, confirmation and artifact storage.

CommandEffect
chain connect NAME HOST --user USERExport connection settings without authenticating.
chain select CONNECTIONRead current forwarding and SOCKS identities.
chain http CONNECTION ID URLReview and execute one bounded request through the selected listener.
chain export CONNECTION ID URLExport that request without sending it.

Connection flow

Create from the TUI

chain connect target server.example --user alice --key /home/alice/.ssh/id_ed25519
  1. Burrow saves a private chain file in the workspace and switches to embedded Hovel.
  2. Submit the prepared throw command. Review and confirm Hovel's plan.
  3. For password/passphrase authentication, answer the private Burrow prompt after confirmation.
  4. Return with Alt+B and inspect the connection before using it.
inspect target
shell target

Existing Hovel input is preserved rather than overwritten. If a draft or confirmation is active, finish or cancel it, then enter the throw command shown in Burrow output. No command is automatically submitted or replayed.

Create from the local shell

These steps work with an already running OpenSSH or Dropbear server and an unused connection name. Replace the endpoint, account and key path.

CHAIN_WORKSPACE=/absolute/workspace
CHAIN_HOVEL="${XDG_CACHE_HOME:-$HOME/.cache}/burrow/hovel/0.4.4/hovel"
burrow --workspace "$CHAIN_WORKSPACE" workspace open
umask 077
burrow --workspace "$CHAIN_WORKSPACE" chain connect target 192.0.2.10 --user tester \
  --port 2222 --key /home/operator/.ssh/lab_ed25519 > "$CHAIN_WORKSPACE/connect.chain.json"
"$CHAIN_HOVEL" throw "$CHAIN_WORKSPACE/connect.chain.json" \
  --workspace "$CHAIN_WORKSPACE" --daemon-endpoint "$CHAIN_WORKSPACE/hoveld.sock" \
  --allow-dangerous --json

Confirm the Hovel plan. --allow-dangerous permits the module classification; launch-key policy still applies. Key/agent chains wait up to 30 seconds for authentication; private challenge flows use the two-minute limit.

Inspect for connected state. Replay against a reserved name is refused. Export again after changed builds or resolved settings. Closing Burrow's connection never stops the target's SSH server; a bare Dropbear server also needs SFTP for file workflows.

Password or encrypted-key authentication

Use two terminals. In A, export a password chain and keep the frontend process alive:

umask 077
burrow --workspace /absolute/workspace chain connect target server.example \
  --user alice --password > /absolute/workspace/password.chain.json

Wait for the exported-JSON message on stderr. In B, submit the file through pinned Hovel:

CHAIN_HOVEL="${XDG_CACHE_HOME:-$HOME/.cache}/burrow/hovel/0.4.4/hovel"
"$CHAIN_HOVEL" throw /absolute/workspace/password.chain.json \
  --workspace /absolute/workspace --daemon-endpoint /absolute/workspace/hoveld.sock \
  --allow-dangerous --json

After confirmation, terminal A asks for the hidden password. Ctrl+C cancels its pending authentication. Encrypted keys use --key PATH --prompt instead.

The private endpoint is one-use, expires after ten minutes and needs its exporting frontend alive. Exported files contain preferences and references, never passwords or key contents. Regenerate expired/used chains. One interactive chain can wait per TUI; cancel rejected Hovel plans with Ctrl+C before staging another.

A supplied --password VALUE can operate without a controlling terminal, but exposes the value in original argv/history. It answers only the target challenge once; jump authentication needs its own keys/agents or interactive input. Prefer hidden entry; see credential limits.

Existing-tunnel HTTP flow

Review HTTP in management

Assume an HTTP service is reachable from the SSH server at internal.example:8080. Create a forward if one does not already exist:

tunnel create target forward 18080 internal.example 8080
chain select target
chain http target target/CREATION_ID http://internal.example:8080/health

Confirm tunnel creation separately. Replace CREATION_ID with the complete selected ID. The URL names the fixed destination, not the local listener. Review connection, direction, listener, destination and URL before approving HTTP.

CLI review and export

burrow --workspace /absolute/workspace chain select target
burrow --workspace /absolute/workspace chain http target target/CREATION_ID http://internal.example:8080/health
# After approving the returned review:
burrow --workspace /absolute/workspace chain http target target/CREATION_ID http://internal.example:8080/health --review HASH --yes
# Alternative: export for a future reviewed Hovel throw.
burrow --workspace /absolute/workspace chain export target target/CREATION_ID http://internal.example:8080/health > /absolute/workspace/health.chain.json

Use the same pinned-Hovel throw shown above with health.chain.json. Each confirmed throw sends a new GET. Export binds current resources; it is not a reconnection recipe.

Throw an existing file in embedded Hovel

Alt+H opens Hovel in the same workspace. Select its operation/chain context, then submit the file:

op use burrow
chain create burrow-chain
chain use burrow-chain
throw /absolute/workspace/health.chain.json --allow-dangerous --json
artifact list --json

If the chain already exists, select it instead of creating it. The automatic TUI handoff sets this context for you. Match artifacts by the throw's run ID. Shell redirection belongs in your local shell, not either management prompt.

Local, reverse and SOCKS routes

RouteTrafficURL destination
LLocal consumer → local listener → SSH → remote service.The forward's fixed destination, such as internal.example:8080.
RServer-origin channel → selected remote listener → SSH → local service.The fixed local destination, not the allocated remote listener port.
D / SOCKSLocal consumer → SOCKS listener → SSH server DNS/connect → destination.Each reviewed hostname and port; no local-DNS fallback.

For reverse selection, create a listener with tunnel create target reverse 0 127.0.0.1 8080. For SOCKS, use proxy create target 1080. Then select its full ID. Reverse consumption needs server-origin forwarding permission and verified Linux listener metadata.

Headless approval and results

"$CHAIN_HOVEL" throw /absolute/workspace/health.chain.json \
  --workspace /absolute/workspace --daemon-endpoint /absolute/workspace/hoveld.sock \
  --allow-dangerous --now --json > health.throw.json 2> health.throw.err
CHAIN_STATUS=$?

Use --now only as explicit authorization; Hovel records it and still enforces module/launch-key policy. A matching preconfirmation is another route. JSON mode without either can print a review prompt and fail at EOF.

Keep stdout, stderr and process status. Check status first, then each Hovel step's state, then parse summary. Errors are not universally JSON. A completed HTTP exchange can return 404 or 500; that is not application health.

HTTP limit / evidenceContract
MethodPlain HTTP GET only; no TLS, custom authentication or redirects.
URLAt most 2,048 bytes; no credentials, query or fragment. Recorded paths must contain no secrets.
ResponseAt most 1 MiB body and 32 KiB headers; no automatic decompression.
ArtifactExact selection, URL, run ID, state, status, byte count and complete-response SHA256. Bodies and headers are discarded.
FailureTimeout, incomplete response and oversized bodies fail. Refusal before traffic may produce no HTTP artifact; persistence failure is not successful collection.

Cleanup and recovery

tunnel remove target/CREATION_ID
proxy remove target
close target

These select different scopes; review only the action intended. Removal waits for admitted bounded consumers and preserves siblings. Connection close ends all its SSH resources; historical evidence remains.

ConditionNext step
Name reservedInspect and use the existing connection, choose a new name or close the verified old creation.
Export refuses after changesCheck build, workspace and full creation identities; explicitly re-export.
Old manager lacks a capabilityInspect resources, then review manager restart before closing them.
Caller disappearedInspect history, artifacts and resources. Do not infer cancellation or send another GET blindly.
SSH works but HTTP failsCheck direction, destination, service availability, DNS and forwarding permission.

Each export contains one configured operation. Uploading, configuring or starting an SSH server and owning its remote cleanup are separate deployment work.
