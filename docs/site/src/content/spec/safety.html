Authorized use and security

Authorized red-team emulation only. Use Burrow only in environments you own or are explicitly authorized to assess, with written scope and approvals. See the security policy.

Current status

MVP 1–4 provide retained OpenSSH connections, shells, forwarding, transfers, scripts, reports and chains. The manual connection recap shows the actual SSH command; host trust follows the accepted LazySSH options recorded in the connection-control decision. Chain-created connections follow Hovel's reviewed throw path. Saved settings contain no passwords or private-key contents.

Run capture and cancellation have explicit storage and ordinary-process-group limits; uncollected output can be lost on owner failure. Local tools run as the local user without a sandbox, and raw socket commands do not receive complete per-command audit. Chain requests preserve explicit selection and confirmation. Commands, script output, reports and artifacts can contain sensitive operational data; keep their workspace private.

Known Hovel runtime limitation

The pinned official Hovel v0.4.2 runtime can crash when concurrent clients access its SQLite workspace. This can interrupt active connections and runs; reconnection remains manual. Hovel follow-up #86 tracks the evidence and proposed upstream fix. The release carries this known limitation and uses the official runtime. Its dedicated regression and two prototype checks run as visible advisory diagnostics; production acceptance checks remain required.

Reporting

Report repository vulnerabilities privately through GitHub security advisories. Keep credentials and third-party target data out of reports.
