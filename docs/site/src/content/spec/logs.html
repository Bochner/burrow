Operation logs

logs or Ctrl+N opens the current workspace’s operation notes in an embedded Vim tab. Use Vim search and navigation normally; mouse-wheel scrolling, Page Up/Down and gg/G are available. Ctrl+N or :q closes the viewer and restores the prior tab, focus and draft. Reopening takes a fresh snapshot. The shortcut is reserved by Burrow in management, file mode and embedded SSH, Hovel and editor tabs; it is not sent to the embedded application. During a confirmation dialog, finish or cancel the dialog first.

The CLI entry is burrow --workspace /canonical/workspace logs, with terminal input. Vim uses Burrow’s private configuration, Catppuccin semantic highlighting and a contrasting timestamp background. NO_COLOR disables syntax colors. Personal Vim configuration and plugins are not loaded. The read-only snapshot is separate from the live log, so even changing Vim options cannot overwrite ongoing records.

Scope and interpretation

Ctrl+L opens a read-only viewer with separate Collected output and Activity log tabs. Tab/Shift+Tab switch tabs, / searches, and Ctrl+L or :qa returns to the previous Burrow screen and draft. Reopening refreshes both snapshots. Like Ctrl+N, Ctrl+L is reserved by Burrow in embedded terminals and waits until an open dialog is dismissed.

Collected output shows commands explicitly registered by run collect, newest collection first, including closed runs. Each entry gives the command, target, execution outcome, capture completeness and separate stdout/stderr previews. Each stream preview contains at most 64 KiB with an explicit truncation notice and the full artifact path; it does not reduce the saved output. Control characters are escaped and stream lines are indented. A missing artifact or unavailable activity log is reported in its own view. Hovel's artifact inventory and the original operation log remain authoritative; viewer snapshots do not create another history.

The owner resolved issue #80 on 2026-09-13: record Burrow-issued operations and shell lifecycle only. Commands and output typed inside interactive SSH shells are not recorded. This is an operation log, not a terminal recorder or a tamper-proof forensic record. Arbitrary tools run inside the Hovel tab are governed by Hovel’s own contracts.

The viewer shows readable, colored summaries of completed operations and failures. Downloads produce one final batch summary with totals, elapsed time and the saved location, including mixed failures or cancellation. Per-file JSON, attempts and implicit discovery remain in the detailed backend log rather than the notes. The viewer is a snapshot; reopen it for later completions.

Detailed backend entries begin with a timestamp with timezone and the operation identity. Workspace, target, correlation ID, status and complete safe structured results follow. Submitted-command records preserve the frontend result, while owner records describe actual work and background completion. A review is not an execution. A saved attempt without a terminal result means the outcome is unknown; inspect the owned resource before retrying. Escaped controls and indented payload lines prevent remote text from creating apparent entry headers. No output is silently truncated by the log writer; existing bounded browsing results retain their incomplete/error labels.

Transfers retain their original get/mget/put identity, every source and actual destination, per-file state, bytes, partial/error details, timing, completion time and aggregate counts. Completion is recorded by the retained owner even after the frontend exits. File contents remain in their files. Working transfers are not automatically registered Hovel evidence.

Storage and failures

Each canonical workspace stores burrow-logs/operations.log in a private 0700 directory with a 0600 file. Descriptor-based path checks reject unsafe ownership, permissions, symlinks and hard links. Cooperating clients serialize appends and snapshots under a filesystem lock and sync writes. Prior entries survive restart; there is no automatic rotation or retention limit.

New target work is refused if its attempt cannot be saved. Cleanup and cancellation still run if logging is unavailable and report the audit failure. Completion-write failure is returned or retained in connection/download status; shell logging failures are reported on frontend exit as well as in shell exit results. A partial record prevents further appends and viewing from claiming a complete snapshot. Preserve the original file and investigate storage before manual repair. No automatic recovery deletes evidence.

Authentication answers, private-key contents and secret-bearing structured fields are excluded. Connection output uses existing safe results and classified authentication errors. This does not guarantee that arbitrary remote output or customer filenames contain no sensitive information; protect these logs as engagement records.

LazySSH’s pinned logging_module.py and logging tests preserve command identity, transfer paths, sizes and success/failure. Burrow intentionally replaces its debug-only/truncated command output and transient per-connection log location with complete safe workspace records and durable transfer totals; it does not reproduce LazySSH’s additive/reset counter behavior.
