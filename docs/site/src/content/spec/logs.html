Operation logs

Use live following for current work, operation notes for recorded actions, and collected output for saved run evidence. Interactive shell keystrokes and terminal bytes are not recorded.

Follow live activity

burrow --workspace /absolute/workspace follow
burrow --workspace /absolute/workspace follow --json

Start follow beside the TUI or agent process. It prints new actions, reviews, progress, results and available run stdout/stderr. Ctrl+C ends only this observer.

The workspace must already have a verified daemon. Following neither initializes it nor approves, executes or collects work. Startup shows current resources, then new observations; historical notes and existing captured bytes are not replayed.

Input acceptance, command exit, capture completeness and collection are separate facts. Ordering is preserved per source; merged observation order is not a global execution timeline.

JSON and gaps

--json or redirected stdout emits one version-1 JSON observation per line. Fields include workspace, timestamps, source, kind and message; correlation IDs and base64 output appear when available. See the logs API.

Each viewer keeps in-memory source cursors. Failures print gap; recovery prints resumed. Daemon changes, overwritten events, replaced logs and vanished runs remain explicit gaps. Restarting follow starts a new live observation; there is no durable resume token or work retry.

Read operation notes

burrow --workspace /absolute/workspace logs --json

This returns {"text":"…"} without opening an editor. In management, logs or Ctrl+N opens a read-only Vim snapshot. Use search, page keys and gg/G; Ctrl+N or :q returns to the previous view.

Read collected output

Ctrl+L opens Collected output and Activity log. Tab switches tabs; Ctrl+L or :qa closes the viewer. Reopening refreshes snapshots. These shortcuts are reserved by Burrow and wait for open dialogs to finish.

Each collected entry shows the command, target, local/remote exit, capture status and separate stream previews. Previews are at most 64 KiB per stream with a full artifact path and truncation notice; saved originals remain complete within their capture budgets.

Use run follow ID for a live run stream and reports for operational Markdown. None of these viewers creates another audit record or collects output.

Storage and failures

WORKSPACE/burrow-logs/operations.log is a private 0600 file in a 0700 directory. Cooperating clients lock and sync appends. Entries survive restart; there is no automatic rotation or retention limit.

New operations are refused if their attempt cannot be saved. Cleanup, cancellation and controller release still proceed and report audit failure. A successful control with auditError can already have accepted bytes; inspect instead of replaying input.

Unsafe paths, ownership, permissions, symlinks, hard links and partial records are refused. Preserve the original log before manual repair. Known credential fields are redacted, but commands and arbitrary output can contain sensitive data; protect logs and redirected feeds.

The log records operations and lifecycle, not a tamper-proof forensic transcript. CI Reports provides build/test evidence separately.
